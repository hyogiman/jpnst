# アニ耳 학습 설계 문서

> 대상: 일본어를 전혀 모르는 **한국어 화자 성인 학습자**
> 목표: 6개월(180일) 후 **일본 애니메이션의 대사를 상당 부분 알아듣는 청해 기초**를 갖춘다
> 형태: 모바일 웹앱(PWA) · 하루 한 화 20~30분 · 매 화 평가

이 문서는 "왜 이렇게 만들었는가"를 정리한 설계 근거입니다. 참고한 앱, 학습과학 연구, 그리고 이 앱에서 내린 결정과 그 한계를 함께 적었습니다. 사실 확인이 어려운 내용은 단정하지 않고 그렇다고 밝혔습니다.

## 1. 요구사항과 대응

| 요청 | 앱에서의 구현 |
|---|---|
| 가나도 모르는 초보자 → 글자부터 | 1장(30화) 전체를 문자에 배정. 히라가나 46자 → 탁음·반탁음 → 요음 → 촉음·장음 → 가타카나 → 확장 가나 순서. 글자마다 한국어 기억법·기원 한자(한자음 연결)·쓰기 연습 패드 |
| 발음을 들을 수 있게 | 모든 가나·단어·예문·대사·대화에 녹음 음성(구글 Chirp 3: HD 신경망 합성, 여성 2·남성 2 목소리를 섞어 씀. 설정에서 한 목소리만 골라 들을 수도 있음). 휴대폰에 일본어 음성이 없어도 재생. 글자 하나는 0.7배속으로 또렷하게. 0.6배 느린 재생, 0.75/1.0/1.25배 대사 재생. 문제·카드의 "다른 목소리" 버튼으로 그 자리에서 다른 목소리로 바꿔 듣기. 모든 녹음은 일본어 음성 인식으로 받아 적어 맞게 읽었는지 검사 |
| 게이미피케이션으로 성장 체감 | 스탬프 카드(도장), 연속 학습(보호권), XP·레벨, 모험가 랭크(F→S), 주간 보스전, 승급 시험, 배지 20종, 능력치·점수 추이·학습 기록 히트맵 |
| 어휘·문법을 충실히 | 단어·표현 1,154개, 문법·표현 196항목, 예문 496개(빈칸 문제용 246개), 애니 대사 139개, 장면 대화 24편. 문법마다 "자세히 보기"(왜 그럴까 · 예문 더 보기 588개 · 비교·주의 · 애니에서는) |
| 지난 내용을 모아 보기 | 노트 탭에서 지금까지 배운 단어·문법(자세히 보기 포함)·대사·인문학을 화별로 모아 보고 검색. 화 목록에서 "이 화 내용 다시 읽기" |
| 지난 내용을 계속 리마인드 (오늘의 복습은 그대로) | 복습 탭의 "누적 복습": 배운 단어·문법(예문·예문 더 보기)·대사·장면 대화에서 20문항씩 끝없이. 종류(골고루·단어·문법·예문·듣기)를 고르고, 아직 안 나온 것·자주 틀린 것을 먼저 냄. 여기서 틀린 항목만 다음 날 오늘의 복습에 다시 나옴 |
| 보기를 보면 답이 너무 쉽게 보임 | 설정의 "문제 난이도"(보기 고르기 / 섞어 풀기 / 주관식): 일본어로 직접 쓰기(로마자·한글 자판 → 가나), 듣고 받아쓰기, 빈칸 직접 쓰기, 가짜 조각이 섞인 배열, 뜻을 떠올린 뒤 스스로 채점. 보기 문제도 소리가 비슷하거나 같은 주제의 말로 보기를 골라 헷갈리게 함 |
| 하루 단위 · 6개월 코스 | 6챕터 × 30화 = 180화. 매주 6화 학습 + 7일째 보스전, 챕터 끝에 청해 특훈과 승급 시험 |
| 하루 학습 후 반드시 평가 | 모든 학습 화의 마지막 단계가 "오늘의 평가"(10문항, 70점 이상 통과). 통과해야 다음 화가 열림 |

## 2. 참고한 학습 앱 분석

아래 앱들의 **공개적으로 알려진 특징**을 참고했습니다. 앱의 세부 기능은 버전에 따라 바뀌므로 "무엇을 배웠는가" 위주로 적었습니다.

| 앱 | 강점 (가져온 것) | 한계 (보완한 것) |
|---|---|---|
| **Duolingo** | 짧은 단위의 학습 경로, 연속 학습(streak)과 보호 장치, XP, 즉각적인 정답·오답 피드백, 틀린 문제를 다시 내는 흐름 | 일본어 과정은 문법 설명이 짧다는 평이 많음 → 이 앱은 문법 카드에 한국어 대조 설명과 예문을 충분히 넣고, 항목마다 "왜 그렇게 되는지"(어원·소리 변화·한국어와의 비교)와 추가 예문을 담은 자세히 보기를 둠 |
| **Anki** | 간격 반복(SRS)의 표준. 복습 시점을 알고리즘이 정해 줌 (최근 버전은 FSRS 알고리즘도 선택 가능) | 덱을 직접 고르고 설정해야 하는 부담, 게임 요소가 거의 없음 → 이 앱은 코스에 SRS를 내장해 "배우면 자동으로 복습 대상에 등록" |
| **WaniKani** (Tofugu) | 기억법(mnemonic)으로 문자를 외우게 하는 방식, 단계형 레벨과 잠금 해제 | 한자 읽기 중심이라 청해와 거리가 있음 → 이 앱은 기억법 방식을 가나에 적용하고, 한자는 "읽기 보조(후리가나)"로만 사용 |
| **Bunpro** | 문법을 예문 빈칸으로 SRS 복습 | 청해·구어 표현 비중이 낮음 → 빈칸 문제 + 문장 듣기 + 어순 배열을 섞음 |
| **LingoDeer** | 아시아 언어 학습자를 위한 체계적인 문법 순서 | 애니 구어(반말·축약·역할어)는 다루지 않음 → 4장 전체를 "애니 말투"에 배정 |
| **Language Reactor / Migaku** (브라우저 확장) | 실제 영상에 이중 자막·사전 조회를 붙여 "진짜 콘텐츠"로 학습 | 초보자에게는 입력이 너무 어려움 → 이 앱은 그 단계로 가기 전의 "다리" 역할. 6장에서 자막 단계(한국어 → 일본어 → 없음) 훈련 후 실제 애니로 넘어가도록 안내 |

**결론(추론):** 초보자가 "애니 청해"라는 목표에 가장 효율적으로 도달하려면
① Duolingo식 **짧고 매일 반복되는 단위 + 즉각 피드백**,
② Anki식 **자동 간격 반복**,
③ WaniKani식 **기억법**,
④ Bunpro식 **예문 기반 문법 복습**,
⑤ 실제 콘텐츠로 넘어가기 위한 **구어·청해 특화 단계**
를 하나의 흐름으로 묶는 것이 합리적이라고 판단했습니다. 기존 앱들은 이 중 한두 가지에 강하지만, "한국어 화자 × 완전 초보 × 애니 청해"라는 조합에 맞춘 것은 찾기 어려웠습니다.

## 3. 학습과학 근거

| 원리 | 연구 | 앱에서의 적용 |
|---|---|---|
| **간격 효과** | 에빙하우스(1885)의 망각 곡선 연구 이후 반복 확인됨. 세페다 등(2006)의 메타분석은 학습 간격을 두는 것이 몰아서 하는 것보다 장기 기억에 유리함을 보고 | 라이트너 상자 방식 SRS: 1 → 2 → 4 → 7 → 14 → 30 → 60일. 틀리면 단계가 절반으로 내려가고 다음 날 다시 출제 |
| **인출 연습(시험 효과)** | 로디거와 카피키(2006): 다시 읽기보다 시험처럼 떠올리는 연습이 1주 후 기억에서 더 우수 | 매 화 워밍업 복습 + 연습 + 평가. "읽고 끝"이 없음 |
| **즉각적 피드백과 오답 재출제** | 형성평가 연구 전반 | 연습 단계에서 틀린 문제는 설명과 함께 정답을 보여 주고 단계 끝에 한 번 더 출제 |
| **바람직한 어려움 · 생성 효과** | 비요크(1994): 스스로 떠올리기·간격·섞기처럼 학습 중의 적당한 어려움은 당장의 정답률을 낮추더라도 장기 기억을 높임("바람직한 어려움"). 슬라메카와 그라프(1978): 스스로 만들어 낸 답이 읽기만 한 정보보다 잘 기억됨(생성 효과) | 문제 화면에는 가나만 보여 주고 한자·로마자 힌트는 숨김 → 답을 고른 뒤 정답 카드에서 공개. 한국어 화자는 한자만 보고도 뜻을 짐작할 수 있어(学生 → 학생) 가나 읽기·청해 연습이 건너뛰어지기 때문. 설정에서 힌트를 다시 켤 수 있음. "문제 난이도"를 올리면 보기 없이 직접 쓰거나 떠올리게 함 |
| **재인보다 회상 · 선다형의 부작용** | 강, 맥더못과 로디거(2007): 정답을 알려 주는 피드백이 있을 때, 단답형(직접 쓰기)으로 연습한 쪽이 선다형으로 연습한 쪽보다 나중 시험 성적이 좋았음. 로디거와 마시(2005): 선다형은 틀린 보기를 정답으로 잘못 기억하게 하는 부작용도 있음. 버틀러와 로디거(2008): 답한 직후의 피드백이 이 부작용을 줄임 | 학습자 피드백("보기를 보면 답이 쉽게 보인다")에 따라 직접 쓰기·받아쓰기·떠올리기 문제를 넣음. 보기 문제는 소리가 비슷한 말로 더 헷갈리게 만들었는데, 이는 틀린 보기를 잘못 기억할 위험도 키우므로 모든 문제에서 답한 직후 정답 카드(가나·한자·뜻·음성)를 보여 줌 |
| **교차 학습 (섞어서 연습)** | 로러와 테일러(2007): 문제 유형을 섞어 연습한 학생이 같은 유형을 몰아서 연습한 학생보다 나중 시험에서 크게 앞섬. 코넬과 비요크(2008): 화가들의 그림을 섞어서 본 쪽이 화가별로 몰아서 본 쪽보다 처음 보는 그림의 화가를 더 잘 맞힘 | 누적 복습은 단어·문법·듣기 문제를 한 세트에 섞고, 같은 날 배운 것끼리 몰지 않고 지난 범위 전체에서 고름 |
| **이중 부호화** | 파이비오(1971): 언어 정보와 이미지·감각 정보를 함께 부호화하면 기억이 강화 | 가나마다 모양 기억법 + 소리 + 기원 한자 + 손으로 쓰기 |
| **이해 가능한 입력 / 출력** | 크라센의 입력 가설(i+1), 스웨인(1985)의 출력 가설. 두 이론 모두 비판과 논쟁이 있음 | 매 화 "오늘의 애니 대사"를 속도별로 듣고(입력), 쉐도잉 3회(출력) |
| **쉐도잉** | 통역 훈련에서 널리 쓰이며, 일본인 영어 학습자를 대상으로 청해 향상을 보고한 연구가 있음(예: 하마다 요의 연구) | 대사 카드의 "따라 말하기" 단계 |
| **자기결정성 이론** | 데시와 라이언: 유능감·자율성·관계성이 내적 동기를 지탱 | 매일 평가로 유능감 확인, 하루 진도 제한 없음(자율성), 인물·장면 중심 콘텐츠 |
| **보상의 역효과 주의** | 레퍼 등(1973): 외적 보상이 원래 좋아하던 활동의 내적 동기를 떨어뜨릴 수 있음(과잉정당화 효과). 하마리 등(2014)의 문헌 검토는 게이미피케이션 효과가 대체로 긍정적이지만 맥락에 따라 다르다고 정리 | 보상을 "학습 결과"(통과, 하나마루, 복습 수)에 연결하고, 오답에 목숨을 깎는 벌점은 보스전에만 한정. 틀려도 무제한 재도전 |
| **어휘 커버리지와 청해** | 네이션(2006) 등: 영어 구어를 충분히 이해하려면 수천 개 단어족이 필요하다는 추정. 반 질란트와 슈미트(2013)는 청해에서 95% 안팎의 어휘 커버리지를 기준으로 논의 | 이 코스(약 1,150개)만으로는 모든 애니를 자막 없이 이해하기 어렵다는 점을 앱 안에서 명시하고, 6장 마지막에 실제 시청 전략을 안내 |

## 4. 한국어 화자 맞춤 설계

- **어순·조사의 유사성**: は=은/는, が=이/가, を=을/를, の=의, も=도, より=보다처럼 대응시켜 설명. は/が 구분은 "은/는 vs 이/가"로 바로 이해 가능.
- **한자음 연결**: 約束=약속, 準備=준비, 世界=세계 등 한자어 단어에 한국 한자음 힌트 표시. 뜻이 다른 "가짜 친구"(大変, 勉強)는 인문학 노트에서 따로 경고.
- **가나 기억법**: 가나의 기원 한자와 한국 한자음을 연결(加 = 더할 가 → か, 美 = 아름다울 미 → み). 한국어 숫자 "이(2)" → い처럼 한국어 발음을 활용한 연상.
- **발음 함정**: 한국어에 없는 유성/무성 대립(か/が), 촉음·장음 박자, う의 원순성 등을 초반에 집중 훈련하고, 비슷한 소리 구별(きて/きって, びょういん/びよういん) 문제를 따로 출제.

## 5. 코스 구조 (180화)

| 장 | 제목 | 랭크 | 핵심 |
|---|---|---|---|
| 1 | 문자의 문 (文字の扉) | F → E | 가나 전체, 인사·리액션·숫자·호칭·こそあど |
| 2 | 기초 문법의 기둥 (文法の柱) | E → D | 명사문, 조사, ます형, 형용사, 비교, 의문사 |
| 3 | 활용의 마법 (活用の魔法) | D → C | 동사 그룹, ない·た·て형, ている, 가능·의지·명령형, 〜んだ |
| 4 | 말투의 비밀 (口調の極意) | C → B | 문말 조사, 인칭, 역할어, 간사이 사투리, 구어 축약, 조건, 추측, 감정 |
| 5 | 이야기의 힘 (物語の力) | B → A | 수수 표현, 수동·사역, 경어, 목적·당위, 이세계·추리 어휘 |
| 6 | 자막 없이 (字幕なしへ) | A → S | 장르별 장면 대화, 빠른 발화 규칙, 감정 대사, 자막 떼기 전략 |

**주간 리듬**: 1~6일째 학습 → 7일째 보스전(그 주 6화 범위 복습)

### 누적 복습과 문제 난이도 (2026-10 추가)
학습자 요청: "오늘자 복습은 그대로 두고, 이제까지 학습했던 내용을 계속 리마인드할 수 있게. 문법 퀴즈·단어 퀴즈 등 다양한 문제로, 문법 예문까지. 한 번에 20개 수준으로, 문제 수는 무제한. 그리고 선택지를 보고 푸니까 답이 너무 쉽게 보인다 — 더 어렵게, 주관식도."

- **범위**: 복습 대상으로 등록된 글자·단어·문법·애니 대사(평가를 본 화의 것)와, 그 화의 장면 대화·소리 구별 짝. 문법은 본문 예문(496개)과 "예문 더 보기"(588개)를 모두 씀
- **고르는 순서**: 항목마다 점수를 매겨 높은 것부터 — 누적 복습에 아직 한 번도 안 나온 것(5점) > 오래전에 나온 것(세트 수에 비례, 최대 4점) + 틀린 비율(최대 3점) + 기억 단계 1~2(1점) + 무작위(0~2점). 바로 앞 세트에 나온 것은 크게 감점. 그래서 세트를 이어 풀면 배운 것 전체를 한 바퀴씩 돌면서, 자주 틀리는 것은 더 자주 나옴
- **종류**: 골고루(단어 8 · 문법 7 · 듣기 4 · 약한 글자 1) / 단어 / 문법·예문 / 듣기
- **문법 문제 만들기**: 예문 마크업에 빈칸이 있으면 그 빈칸, 없으면 그 문법의 핵심 형태(다른 예문의 빈칸 정답, 제목의 〜ほど·〜べき 같은 형태)가 든 토큰을 찾아 비움("예문 더 보기" 588개 중 266개). 그 밖에 조사 빈칸, 문장 배열(가짜 조각 포함), 문장 뜻, 문법 뜻(제목이 일본어 형태인 112항목만), 듣고 빈칸 받아쓰기를 섞음
- **헷갈리는 보기**: 단어는 ① 소리가 1~2박만 다른 말(きれい → きらい·くらい·おれい) ② 같은 한자를 쓰는 말 ③ 같은 화(같은 주제)의 말 ④ 가까운 날의 말 순서로 고름. 뜻에 같은 낱말이 들어 있는 말(알다 / 알다, 이해하다)과 뜻이 같은 말은 빼서 정답이 둘이 되지 않게 함. 문장 뜻 보기는 같은 문법의 다른 예문(구조가 같음)에서 먼저 고름. 조사 빈칸·가짜 조각에서는 서로 바꿔 써도 맞는 짝(방향의 へ/に, 나열의 と/や, 관계절의 の/が, 출발점의 から/より, 会う의 に/と)을 빼서 정답이 둘인 문제가 나오지 않게 함(기존 레슨 빈칸 문제에도 적용)
- **난이도별로 바뀌는 문제**: 글자 소리 고르기 → 로마자로 쓰기 · 듣고 글자 고르기 → 받아쓰기 · 뜻 → 일본어 고르기 → 직접 쓰기 또는 조각 맞추기 · 듣고 뜻 고르기 → 받아쓰기 또는 떠올리기 · 빈칸 고르기 → 빈칸 직접 쓰기 · 문장 배열 → 가짜 조각 섞기 · 문장 듣고 뜻 → 듣고 빈칸 받아쓰기 또는 떠올리기 · 소리 구별 → 들리는 말 쓰기. 섞어 풀기는 바꿀 수 있는 문제의 약 45%, 주관식은 모두. 장면 대화 이해(한국어로 답해야 해서 자동 채점이 어려움)와 짝 맞추기는 보기 문제로 둠
- **직접 쓰기 입력**: 로마자를 일본 컴퓨터의 로마자 입력과 같은 규칙으로 가나로 바꿔 미리 보여 줌. 앱이 1장에서 보여 주는 로마자 표시(onna, kin'en, paathii)를 그대로 따라 쳐도 맞도록 두 규칙을 맞췄고(てぃ는 thi로 표시), 단어·예문 토큰 2,589개의 로마자 표시를 다시 가나로 바꿔 모두 맞게 채점되는지 검사함(`tools/drill-test.js`). 한글 자판을 바꾸지 않고 쳐도 되도록, 한글 자모를 2벌식 자판의 글쇠로 되돌린 뒤 바꿈(노ㅑ → shi → し, 뭐 → nj). 일본어 자판이 있으면 가나·한자로 바로 써도 됨
- **채점**: 맞음 / 맞음(표기 주의) / 틀림. 소리는 같고 표기만 다른 것(장음 ー/う/お, ぢ·づ, 조사 は·へ·を를 わ·え·お로 친 것, では ↔ じゃ, 끝의 っ)은 맞음으로 치고 바른 표기를 알려 줌. 길이(おばさん ↔ おばあさん)·촉음(きた ↔ きった)·탁음(か ↔ が)이 다르면 틀림 — 청해에서 구별해야 하는 차이이기 때문. 뜻이 같은 다른 단어(쓰다: かく/にがい)도 정답
- **스스로 채점**: 뜻을 일본어 → 한국어로 떠올리는 문제는 한국어 답의 표현이 너무 다양해 자동 채점이 어려우므로, 보기 없이 속으로 떠올린 뒤 정답을 보고 "알았어요/몰랐어요"를 고름(Anki 방식). 기록은 자기 공부용이므로 정직하게 고르는 것을 전제로 함
- **기록**: 오늘의 복습 일정은 건드리지 않고, 누적 복습에서 틀린 항목만 다음 날 오늘의 복습에 다시 나오게 함(맞힌 것으로 간격을 늘리지는 않음 — 간격 반복의 일정은 오늘의 복습이 맡음). 누적 복습의 기록(세트 수, 항목별 마지막 출제 세트·맞힌 수·틀린 수)은 학습 기록 백업에 함께 들어감
- **검증**: `tools/drill-test.js`가 입력 변환(로마자·한글 자판), 채점 규칙, 난이도 3단계 × 종류 4가지 × 40세트(9,600문항)와 180화 전체의 레슨·평가·보스전·청해 특훈·승급 시험 문제를 만들어 보기 중복·정답 누락·채점 불가 문항이 없는지 검사. `tools/smoke.js`가 실제 화면에서 직접 쓰기(로마자 입력)·스스로 채점·누적 복습 4세트를 끝까지 풀어 봄

## 8. 기술 설계 요약

- **순수 HTML/CSS/JS**(빌드 도구 없음) — GitHub Pages 등 어디서나 정적 호스팅 가능, 단일 HTML 파일로도 동작
- **음성**: 구글 Cloud Text-to-Speech의 신경망 음성 **Chirp 3: HD**로 미리 만든 녹음 클립 10,630개(섞어 듣기용 2,666개 + 목소리 고르기용 7,964개, 서로 다른 소리 8,202개. 여성 Despina·Sulafat, 남성 Algenib·Fenrir, 96kbps MP3, 약 124MB)를 챕터별 묶음 파일로 배포. 묶음 이름에 내용 해시를 붙여 음성을 다시 만들면 캐시가 자동으로 바뀜. 필요한 구간만 먼저 받아 재생하고, 받은 묶음은 오프라인용으로 캐시. 녹음이 없거나 불러오지 못하면 기기 TTS(Web Speech API)로 대체. 재생은 기기 안의 파일이라 구글 비용은 만들 때 한 번만 듦
  - **목소리 배분**: 글자(가나)는 Despina 한 목소리·0.7배속 / 단어는 네 목소리에 고르게(소리 구별 짝 かき·かぎ는 같은 목소리) / 예문·애니 대사는 말투(역할어)로 성별을 정함 — おれ·お前·ぞ 등은 남성, わよ·かしら 등은 여성, 나머지는 고르게 / 장면 대화는 인물마다 목소리 하나를 고정
  - **목소리 고르기 (설정)**: 학습자 요청으로 추가. 섞어 듣기(기본·추천) 대신 네 목소리 중 하나를 고르면 장면 대화를 뺀 모든 음성이 그 목소리로 나옴. 장면 대화는 인물 구분이 필요해 인물별 목소리를 유지. 장면 대화를 뺀 1,991개 항목을 네 목소리로 하나씩 더 만들되(키: `Sulafat|문장`), 섞어 듣기용과 조건이 같은 소리는 다시 만들지 않고 같은 자리를 가리킴. 목소리별 녹음은 챕터·목소리마다 묶음(`pack2-sulafat-xxxx.mp3`)으로 나눠, 고른 목소리의 묶음만 불러옴. 찾는 녹음이 없으면 섞어 듣기용 녹음으로 대신 재생. 문법 자세히 보기의 '예문 더 보기' 580개는 앱 용량(약 15MB 추가) 때문에 섞어 듣기용 한 목소리로만 만듦
  - **다른 목소리 버튼 (2026-10 추가)**: 학습자 요청으로, 문제·카드에서 그 자리에서 다른 화자로 바꿔 들을 수 있게 함. 누를 때마다 다음 목소리 녹음을 재생하고 이름을 보여 주며, 방금 들은 녹음과 같은 소리(색인의 위치가 같은 것)는 건너뜀. 한 목소리의 발음이 애매할 때 다른 화자로 확인하는 용도이자, 여러 화자에 노출되는 효과도 있음
  - **다시 만들기 비용 줄이기**: `tools/audio-manifest.json`에 녹음마다 만든 조건(목소리·입력·읽기 지정·속도·횟수·자르기 방식)의 서명을 남겨, 조건이 같으면 지금 묶음의 MP3를 그대로 다시 씀(요청·재압축 없음, 결과 파일이 바이트 단위로 같음을 확인). 키는 Claude 클라우드 환경의 네트워크 시크릿으로 두어(헤더 `X-Goog-Api-Key`) 작업 공간·대화에 남지 않게 함
  - **왜 여러 목소리인가**: 말소리 지각 연구에서 사람들은 목소리를 익힌 화자의 말을 낯선 화자의 말보다 잡음 속에서 더 잘 알아들었습니다(Nygaard, Sommers & Pisoni, 1994). 즉 한 목소리로만 공부하면 '그 목소리라서' 맞히는 몫이 생길 수 있습니다. 또 일본인에게 영어 /r/·/l/를 가르친 고변이 음성 훈련(HVPT) 연구에서는 여러 화자로 훈련할 때 처음 듣는 화자에게도 잘 일반화되고, 한 화자로만 훈련하면 일반화가 약하다고 보고했습니다(Logan, Lively & Pisoni, 1991; Lively, Logan & Pisoni, 1993). 다만 이 원 연구들은 참가자가 적었고, 166명으로 사전 등록해 다시 해 본 재현 연구에서는 두 방식 모두 실력이 늘었으며 여러 화자 훈련의 추가 이점은 있더라도 아주 작다는 결과가 나왔습니다(Brekelmans 외, 2022, Journal of Memory and Language). 그래서 "여러 목소리가 반드시 더 낫다"기보다, ① 한 목소리에 익숙해져 맞히는 몫을 줄이고 ② 수많은 성우가 나오는 애니에 미리 대비하며 ③ 학습에 손해가 거의 없다는 점에서 네 목소리를 섞었습니다
  - **음성의 변천 (HTS → VOICEVOX → 구글)**
    1. 처음에는 HTS 방식(Open JTalk) 음성을 썼으나, 실사용 피드백에서 "기계음 같고, あ가 '아—'가 아니라 'ㅇ!'처럼 끊긴다"는 문제가 나와 교체했습니다. 클립을 측정해 보니 あ의 소리 구간이 0.12초(い 0.08초, ん 0.04초)에 불과했고, 마지막 20ms 사이에 음량이 약 −18dB에서 −41dB로 뚝 떨어졌습니다. 원인은 ① HTS 합성이 글자 하나를 아주 짧게 만들고 음질 자체도 기계적이라는 점, ② 앞뒤 무음을 자르는 처리(최대 음량의 2% 이하 구간을 잘라 냄)가 끝의 여운까지 잘라 낸 점입니다
    2. 신경망 합성 VOICEVOX(core 0.15, VOICEVOX:冥鳴ひまり·玄野武宏)로 교체: 무음을 자르지 않고 끝 30ms만 페이드, 글자 하나는 모음 길이 약 0.4초로 늘림, 말소리 구간 음량(RMS) 기준으로 두 음성의 크기를 맞춤. 읽기 검사도 강화해, 합성기가 실제로 읽을 발음(AudioQuery)을 후리가나와 비교하되 따로 떨어진 조사 は·へ·を만 わ·え·お로 인정. 이전 검사는 모든 は를 わ로 간주해 넘겼던 오독 6건(はち→"와치", はみがき, しはい, つかう→"쓰카아", あらう, 웃음소리 ふはは)을 찾아 고침
    3. 구글 Chirp 3: HD로 교체: "青(あお)가 전자음과 섞인 소리라, 익숙해서 맞히는 것이지 정말 알아듣는 것인지 모르겠다"는 피드백을 받고 측정한 결과 ① 48kbps MP3 압축 때문에 4~11kHz 대역에 '스펙트럼 구멍'(원본보다 30dB 이상 비어 버린 칸)이 말소리 구간의 5.5~9.7% 생겼고(96kbps에서는 1% 미만), 이것이 금속성 '전자음'처럼 들리는 원인 중 하나였습니다. ② 남성 음성의 맑기(조화음 대 잡음비, HNR)가 5.5dB로 여성(14.4dB)보다 크게 낮아 숨소리·잡음이 많았습니다. ③ 성별마다 목소리가 하나뿐이라 그 목소리에 익숙해질 위험도 있었습니다. 그래서 일본어 Chirp 3: HD 목소리 30개(여성 14·남성 16)로 같은 글자·단어·문장·애니 대사를 만들어 비교 페이지를 만들고, 학습자가 직접 듣고 네 목소리를 골랐습니다. 고른 목소리의 맑기는 Despina 14.4, Sulafat 15.7, Algenib 9.8, Fenrir 9.5dB(青와 문장 두 개의 평균. VOICEVOX와 측정 문장이 조금 달라 참고용이며, 고르는 기준은 귀로 들은 인상)
  - **읽기 맞추기**: Chirp 3: HD에는 일본어 요미가나로 읽기를 지정하는 기능이 있습니다. 6개 말을 두 가지 읽기로 지정해(日本 にほん/にっぽん, 今日 きょう/こんにち, 一日 いちにち/ついたち, 上手 じょうず/うわて, 私 わたし/わたくし, 何 なに/なん) 만든 소리를 각 읽기를 가나로 쓴 문장의 소리와 소리 모양(MFCC+DTW: 음색 지문을 빠르기 차이를 맞춰 비교)으로 견준 결과, 12건 중 11건이 지정한 읽기 쪽에 더 가까웠습니다. 그래서 ① 한 글자 한자(何·方·上처럼 읽기가 여러 개인 것)는 후리가나로 바꿔 넣고 ② 두 글자 이상 한자는 읽기를 지정하며 ③ 지정이 무시될 경우를 대비해 사전(Open JTalk)의 기본 읽기가 후리가나와 다른 말 16개(日本→にほん, 九時→くじ, 七時→しちじ, 辛い→からい, 一回→いっかい, 達者→たっしゃ 등)는 아예 가나로 넣었습니다. 가나만 있는 말에는 지정 기능이 거부되므로(API 오류) 가나 글자는 그대로 넣되 ヲ·ヂ·ヅ는 소리가 같은 オ·ジ·ズ로, 인사말 こんにちは·こんばんは의 は는 わ로 바꿔 넣음
  - **가장 맑은 소리 고르기** (지금은 아래 '맞게 읽었는지 검사'를 통과한 후보 중에서): Chirp 3: HD는 같은 입력도 만들 때마다 조금씩 다르게 말하고, 가끔 숨이 섞인 '아…'가 나옵니다(예: Zephyr 목소리로 같은 あ를 세 번 만들었더니 맑기 17.7 / 11.4 / 3.1dB). 그래서 글자는 4번, 단어는 3번, 문장은 2번 만들어 맑기가 가장 높은 것을 고르고(길이가 다른 것들과 크게 다르면 감점), 모두 흐리면(짧은 말 12dB, 문장 10dB 미만) 몇 번 더 만들어 고릅니다. **고르는 기준의 함정과 수정**: "ハ가 숨소리처럼 들린다"는 피드백을 받고 후보를 하나하나 재 보니, 구글 음성은 가끔 모음까지 속삭이듯(무성음) 말하는데 맑기(조화음 대 잡음비)는 성대가 울린 칸만 보고 재므로 이런 후보가 오히려 높게 나왔습니다(예: Fenrir의 イ — 맑기 20.5로 후보 중 가장 높았지만 성대 울림이 뚜렷한 칸은 0%, 실제로 앱에 들어가 있었음). 그래서 '엄격한 울린 비율'(말소리 구간 중 주기성 0.7을 넘고 최대보다 25dB 낮은 소리 이상인 10ms 칸의 비율)을 만들어 점수 = 20×울린 비율 + 맑기(25에서 자름)로 고르고, 울린 비율이 낮으면(글자 0.5, 짧은 말 0.3, 문장 0.25 미만) 더 만들게 했습니다. 글자는 히라가나·마침표를 붙인 표기로도 2번씩 더 만들어 후보를 늘렸습니다(は·へ는 조사 わ·え로 읽힐 수 있어 히라가나 제외). 결과: 울린 비율 0.3 미만인 글자가 Algenib 29개 → 0개, Fenrir 13개 → 2개(は: Algenib 0.19 → 0.46, Fenrir 0.29 → 0.49 / ひ: Fenrir 0.39 → 0.97). 단어·문장은 남성 목소리에서 0.25 미만이 Algenib 492개 → 387개, Fenrir 296개 → 226개로 줄었지만, 이 둘은 목소리 결 자체가 낮고 거칠어(울린 비율 중앙값 단어 0.39·0.44, 여성 0.64·0.69) 더 만들어도 크게 오르지 않았습니다. 그래서 숨소리처럼 들리면 설정에서 여성 목소리를 고르도록 안내. 다시 고르는 데 든 요청은 3,112건·10,704자. 그래도 울린 비율이 0.45 미만인 글자 14개는 후보를 6개씩 더 만들어 봤지만 2개(Sulafat す 0.41 → 0.56, Fenrir ひゃ 0.43 → 0.69)만 나아졌습니다. 남은 것은 대부분 남성 목소리의 さ행(サ·シ·セ·シャ 등)으로, 천천히 읽으면 'ㅅ·쉬' 바람 소리가 길어져 울린 비율이 낮게 나오는 글자 자체의 성질입니다. 참고로 실제 말에서는 무성 자음 사이·뒤의 い·う가 속삭이듯 약해지는 '모음의 무성화'(です → '데s', すき → 's키')가 흔하므로, 단어·문장에서 く·す가 바람 소리처럼 들리는 것은 자연스러운 일본어이고 청해 연습에도 필요합니다(**정정**: 이 설명은 단어·문장 속의 현상에만 맞습니다. 한때 "つ 소리가 이상하다"는 피드백을 이 설명으로 넘겼는데, 나중에 음성 인식으로 받아 적어 보니 글자 하나 つ 녹음 5개 중 4개가 あ·え로 받아 적히는 등 실제로 잘못 읽힌 녹음이었습니다. 아래 '맞게 읽었는지 검사' 참고) 점검 결과 맑기 중앙값은 여성 목소리 18.1dB, 남성 12.6dB, 글자(가나)는 가장 낮은 것도 15.9dB였습니다. 남성 목소리는 목소리 결 자체가 낮고 거칠어 여러 번 만들어도 크게 오르지 않았으므로(예: サッカー 6번 모두 6.1~6.6dB) 숫자가 낮다고 고장 난 소리는 아닙니다. 또 똑같은 요청에는 똑같은 소리가 돌아오는 경우가 많아 실제로 서로 다른 후보는 계획보다 적었습니다(1,978개 중 850개에서 후보 일부가 같은 파일). 그래서 다음 생성부터는 두 번째 요청부터 음량 값을 0.05dB씩 바꿔(들리지 않는 차이, 음량은 뒤에서 다시 맞춤) 매번 새로 만들게 했습니다. 앞뒤는 최대 음량보다 30dB 낮은 소리부터를 말소리로 보고 앞 0.08초(글자 0.12초)·뒤 0.18초만 남김. 처음에는 소리 끝이 잘리지 않게 −50dB 기준으로 넉넉히 남겼는데, 구글 음성이 말하기 전에 넣는 작은 숨소리·잡음(최대보다 35~55dB 낮음)까지 남아 "글자를 누르면 1초쯤 쉬었다가 소리가 난다"는 피드백을 받았습니다. 재 보니 글자 녹음의 말소리 시작이 중앙값 0.60초(최대 1.41초)였고, 기준을 바꿔 0.16초(최대 0.19초)로 줄였습니다. 숨소리가 30dB 기준을     - **판정 방법**: 받아 적은 글(한자·숫자·알파벳 포함)을 pyopenjtalk로 발음 가나로 바꿔 박(모라) 단위로 비교. 단어·문장은 장음·촉음까지 구별하고(ここ/こうこう, おばさん/おばあさん, うん/ううん), 가나 한 글자는 인식기가 キュ를 "九(きゅう)"처럼 늘려 적는 버릇이 있어 장음 차이만 넘어감. 문장은 8%(최소 1박)까지의 차이를 인식기 오차로 보되, 조사 자리가 ハ·ヘ로 들리면 틀린 것으로 봄(인식기가 は를 글자 그대로 적었으면 '불확실'로만 표시하고 확실히 맞은 후보를 먼저 찾음). 문장 사이에 긴 쉼이 있으면 인식기가 한쪽을 통째로 빠뜨리는 일이 있어(テストは…でした。きょうです。→ "きょうです") 쉼에서 나눠 받아 적은 것도 함께 봄. 둘 중 하나라도 맞으면 통과
    - **고르는 방법**: 후보마다 앱에 넣을 최종 소리를 검사해 맞는 것 중에서만 고르고(첫소리가 온전한 후보 먼저, 두 인식기가 다 맞힌 후보를 조금 더 우선, 그다음 맑기), 마지막에 MP3로 압축한 소리로 한 번 더 확인(아래 ②). 맞는 후보가 없으면 같은 입력으로 몇 번 더 → 입력을 바꿔(마침표·가나·가타카나·한자 그대로, 글자는 0.85·0.5배속) 더 만들어 봄. 첫소리가 잘렸을 수 있어 앞을 덜 자른 소리도 함께 검사하고, 크게 난 짧은 첫소리(げっ·はっ 등)는 숨소리로 보고 지우지 않음. 뚝 끊긴 녹음은 무음을 덧붙이고 고를 때 감점
    - **가나 속도 0.5 → 0.7배속**: 어려운 글자 21개 × 네 목소리 × 세 속도 × 두 표기(가타카나·히라가나)를 만들어 받아 적어 보니 맞은 비율이 0.5배속 58.6%, 0.7배속 62.8%, 0.85배속 62.5%로, 아주 느리게 읽힐 때 오히려 잘못 읽는 일이 조금 많았습니다. 가타카나 입력(68%)이 히라가나(55%)보다 나아서 가타카나를 기본으로 하고, 다른 표기는 후보를 늘리는 데 씀
    - **고친 뒤 다시 검사해서 드러난 것 (네 가지 더 고침)**: 위 방식으로 고른 녹음을 앱에 든 MP3 그대로 다시 받아 적고, 고르는 데 쓰지 않은 Whisper로도 받아 적어 보니 네 가지 문제가 더 있었습니다.
      ① **첫소리가 잘린 채 온 후보**: 구글 음성은 후보의 약 7%를 말소리 한가운데서 시작하는 소리로 보냅니다(캐시의 후보 4,000개를 재 보니 처음 5ms가 최대보다 40dB 낮은 소리보다 큰 것이 6.6%, 정상인 후보는 대개 −60dB 아래의 무음으로 시작). 예를 들어 Despina의 つよい는 앱에 들어 있던 녹음이 처음 1ms부터 −22dB(つ의 마찰음 한가운데)로 시작해 す처럼 들릴 수 있었고, 같은 입력으로 만든 다른 후보들은 대부분 −71~−85dB의 무음으로 시작했습니다. 음성 인식은 이런 녹음도 대개 맞게 받아 적고(強い 같은 흔한 말은 더욱), 맑기·울린 비율 점수는 첫 무성 자음이 잘린 후보를 덜 시끄럽게 봐서 걸러지지 않았습니다. 앱 녹음 중 566개(5.3%, 단어 388개·문장 168개·가나 9개 등)가 이랬습니다 → 이런 후보를 크게 감점하고, 맞게 읽은 후보 중에서도 첫소리가 온전한 것을 먼저 고르며, 모두 이러면 더 만들게 함(`hot_head`)
      ② **MP3로 압축한 뒤에만 틀리는 녹음**: 고를 때는 압축 전 소리를 검사했는데, MP3로 압축한 소리를 다시 받아 적으니 10,630개 중 139개가 틀리게 받아 적혔습니다. 고를 때 끝내 맞는 후보가 없던 23개를 빼면 116개(1.1%)가 압축 전에는 맞았던 녹음으로, 대개 약하게 난 첫 박이 빠지는 아슬아슬한 녹음이었습니다(はやくしろ → やくしろう, くそ、だまされた → だまされた) → 마지막에 앱에 넣을 MP3 그대로 다시 받아 적어, 맞지 않으면 다음 후보로 넘어가게 함
      ③ **두 인식기가 함께 놓치는 가나**: 가나 한 글자는 ReazonSpeech·SenseVoice가 비슷한 소리를 같이 놓칠 때가 있었습니다. SenseVoice는 짧은 소리를 중국어 한자로 적는 버릇이 있어(ぱ → 怕, ちゅ → 超, ん → 嗯) 사실상 ReazonSpeech 한 표로 정해진 셈이었고, Whisper로 받아 적으니 섞어 듣기용 ぱ는 か(ReazonSpeech도 か), ぎょ는 きょう(ReazonSpeech도 きょう), Sulafat의 ぜ는 せー(ReazonSpeech도 せ)로 들렸습니다 → 가나 한 글자와 소리 구별 짝은 **두 인식기 중 하나와 Whisper가 모두 맞게 적은 녹음**을 고름(지금 녹음이 이 조건을 넘으면 그대로 두고, 아니면 후보 중에서 다시, 그래도 없으면 같은 속도로 몇 개 더 만듦). Whisper도 흔한 말 쪽으로 끌려가는 버릇(たいがく → 大学, すいか → 追加)과 짧은 소리를 한자로 적는 버릇(しゅ → 主, ちゅ → 中: 읽기를 하나로 정할 수 없어 '안 맞음'으로 나옴)이 있어, Whisper가 안 맞다고 한 것이 모두 잘못 읽은 녹음은 아닙니다. 그래서 Whisper만으로 고르지 않고 세 인식기 중 둘 이상이 맞는 쪽을 찾는 데 씀
      ④ **조사 は·へ를 '하·헤'로 읽은 문장**: 두 인식기가 は를 글자 그대로 적으면 발음 변환(pyopenjtalk)이 문맥상 조사로 보고 늘 '와'로 읽어서, 구글 음성이 조사를 '하'로 읽어도 판정이 놓칠 때가 있었습니다(조사 자리를 葉·派처럼 다른 한자로 적을 때만 잡힘). 한자를 가나로 바꿔 넣은 입력으로 고른, 조사 は·へ가 있는 문장 526개를 Whisper로 받아 적어 보니 34개가 다르게 적혔습니다(どこかへ行きたい → "どこか兵器隊" 다섯 목소리 모두, 京都へ行きました → "京都兵きました", スーパーへ → "スーパー弊", お前は敵じゃない → "お前派適じゃない", お兄さんは背が → "お兄さんを派生が", そんなことは知らぬ → "そんなこと走らぬ") → --redo로 준 조사 문장은 Whisper 표도 받고, Whisper와 맞는 후보가 없으면 한자 그대로 넣은 입력부터 더 만들어 봄. 34개 중 30개는 세 인식기가 모두 맞게 적는 녹음으로 바뀌었고, 남은 4개는 판정 쪽 한계(Whisper가 うち를 家로 적으면 いえ로 읽힘 3개, かたじけない를 形けない로 적음 1개)입니다. 이 검사는 위험이 큰 526개에만 했으므로, 한자 그대로 넣은 문장에도 조사를 잘못 읽은 것이 드물게 남아 있을 수 있습니다(같은 Whisper 표본에서는 한자 그대로 넣은 문장의 조사 오류는 따로 보이지 않았음)
      덧붙여 인식기가 かく를 描く로 적으면 발음 변환이 えがく로 읽어 맞게 읽은 녹음도 틀린 것이 되던 판정 오류를 고쳤습니다(이 앱의 かく는 모두 かく로 읽으므로 描를 書로 바꿔 읽음). 趣味は絵をかくことです의 세 녹음(Despina·Sulafat·Algenib)이 이 때문에 '맞는 후보 없음'이었고, 그중 Algenib 녹음은 실제로도 조사를 이상하게 읽은 것이었습니다(Whisper: 趣味派へを描く…)

- **구글 플레이 판 (2026-10 추가)**: 같은 코드에 `ANIMIMI_STORE=play`를 주어 만든 앱 번들(AAB). 출시 절차는 [PLAY-STORE.md](PLAY-STORE.md)
  - **정한 것**: 만 18세 이상 · 홈과 나(기록) 화면 아래 배너 1개 · 광고 제거 판매 없음 · 보상형 광고 없음
  - **광고 위치**: 배너는 화면을 오가는 곳(홈·나)에만 두고, 레슨·평가 중이나 창이 열려 있을 때는 숨김. 멀티미디어 학습 연구의 '일관성 원리'(학습과 관계없는 그림·소리·글을 빼면 더 잘 배운다 — Mayer)와 인지 부하 이론의 '외재적 부하'(Sweller)를 따른 것. 구현은 화면이 바뀔 때마다(`#app`·`#overlay` 변화 감시) 지금 화면이 홈·나인지 보고 배너를 보이거나 숨김. 배너는 아래 탭 막대 바로 위에 붙이고, 배너 높이만큼 본문 아래 여백(`--ad-h`)과 알림(토스트) 위치를 올려 내용을 가리지 않게 함
  - **보상형 광고를 넣지 않은 이유**: '광고를 보면 보상'이 경험치·보호권 같은 학습 보상과 섞이면, 공부가 보상을 얻는 수단처럼 느껴질 수 있음. 흥미 있는 활동에 '하면 주는' 보상을 미리 약속하면 내적 동기가 줄어들 수 있다는 과잉정당화 연구(Lepper, Greene & Nisbett, 1973)와 메타분석(Deci, Koestner & Ryan, 1999)이 있어, 7장의 '보상은 학습 행동에만' 원칙과 맞지 않음
  - **광고 제거를 팔지 않은 이유**: ① 판매에는 결제 프로필·인앱 결제 연동·환불 처리가 필요하고, 개인 개발자는 판매 시 주소가 스토어에 공개된다는 보고가 많음 ② 같은 내용을 광고 없이 쓰는 웹판(2nhyeok.kr)과 직접 설치판이 있어 살 이유가 약함 ③ 수익보다 '스토어에 직접 올려 보는 경험'이 목적. 나중에 판다면 **별도 유료 앱보다 같은 앱의 1회 구매(인앱 상품)**: 무료로 낸 앱은 유료로 바꿀 수 없고(플레이 규정), 별도 앱은 학습 기록·평점·리뷰가 나뉘며 빌드를 둘 관리해야 하고, 새 앱마다 비공개 테스트를 다시 거쳐야 할 가능성이 큼
  - **18세 이상인 이유**: 구글 클라우드 서비스별 약관에 생성형 AI 서비스를 18세 미만이 쓰는(쓸 가능성이 큰) 서비스와 함께 쓰지 못하게 하는 조항이 있음. Chirp 3: HD 음성 합성이 여기에 들어가는지, 미리 만든 녹음을 배포하는 것도 해당하는지가 분명하지 않아 조심스러운 쪽을 택함
  - **동의·개인정보**: 구글 동의 도구(UMP)로 동의가 필요한 지역(EU·영국 등)에서만 동의 화면을 띄우고, 그때만 설정에 '광고 개인정보 설정'을 보여 줌. 광고 내용 등급은 T(청소년)까지. 개인정보처리방침(`privacy/index.html`)과 오픈소스 라이선스 화면(빌드할 때 `licenses.txt` 생성)을 앱 설정에 연결
  - **서명**: Play 앱 서명(구글이 앱 서명 키 보관) + 업로드 키. 업로드 키는 자동 빌드가 main에서 처음 한 번 만들어, Secrets의 비밀번호로 암호화한 PKCS12 파일로 저장소에 둠. 이 키만으로는 플레이에 아무것도 올릴 수 없고(계정 접근이 필요), 잃어버리면 재설정을 요청할 수 있어 공개 저장소에 두는 위험이 작다고 판단
  - **직접 설치판과의 관계**: 앱 ID가 같아 기록 형식도 같지만, 서명이 달라 서로 덮어 설치되지 않음(백업으로 옮김). 직접 설치판에도 광고 코드가 들어 있지만 초기화하지 않고, 광고 SDK의 앱 측정도 초기화할 때까지 미루도록(`DELAY_APP_MEASUREMENT_INIT`) 설정. 플레이 판은 GitHub 새 버전 확인을 끔

## 9. 한계와 현실적인 기대치

- **6개월 후의 수준**: 문자·기초 문법·구어 패턴·약 1,150개 어휘를 갖추면 일상물·학원물의 쉬운 대사와 자주 나오는 표현은 상당 부분 알아들을 수 있습니다. 그러나 모든 애니를 자막 없이 완전히 이해하려면 이후에도 실제 시청과 어휘 확장이 필요합니다. 참고로 미국 국무부 외교연수원(FSI)은 영어 화자 기준 일본어를 가장 어려운 등급(약 88주 집중 과정)으로 분류합니다. 한국어 화자는 어순·한자어 덕분에 훨씬 유리하지만, 이에 대한 공식 수치는 없습니다.
- **합성 음성**: 구글의 최신 신경망 음성이라 자연스럽지만, 실제 성우의 연기(감정·속도 변화)와는 다릅니다. 같은 입력도 만들 때마다 조금씩 달라 가장 맑은 것을 자동으로 골랐지만, 1만여 개 녹음을 사람이 모두 들어 본 것은 아닙니다. 읽기는 후리가나대로 넣거나 지정했고, 만든 소리를 음성 인식으로 다시 받아 적어 맞게 읽은 것만 고릅니다(위 '맞게 읽었는지 검사'). 다만 인식기도 틀릴 수 있어 사람이 모두 들어 본 것과 같지는 않습니다. 고저 악센트는 합성기의 추정을 따르므로 표준 악센트와 다를 수 있습니다. 단어 음성은 읽기별로 하나라서, 읽기가 같고 악센트가 다른 단어(ちかい: 近い/誓い)는 같은 음성을 씁니다.

## 10. 기업교육 적용 관점 (교육 담당자용 메모)

이 앱의 구조는 언어 교육이 아닌 기업교육에도 옮겨 쓸 수 있는 패턴을 담고 있습니다.

1. **마이크로러닝 + 매일 형성평가**: 20분 단위 학습의 끝에 반드시 10문항 확인 → 이수율이 아니라 "이해 여부"를 매일 측정
2. **간격 반복 복습 자동화**: 신입 온보딩, 제품 지식, 규정 교육처럼 "잊으면 안 되는" 지식에 1·2·4·7·14·30일 복습 알림 적용
3. **주간 보스전 = 누적 퀴즈 이벤트**: 한 주 학습 범위를 섞어 출제하는 주간 도전 과제(인터리빙 효과)
4. **챕터 승급 시험 = 역량 레벨 인증**: 영역별 점수(지식·적용·청취/커뮤니케이션 등)로 피드백
5. **인문학 한 스푼**: 기능 교육에 짧은 교양 읽을거리와 질문을 붙여 사고를 넓히는 장치
6. **보상 설계 주의**: 포인트·랭킹이 내적 동기를 대체하지 않도록 "학습 행동"에만 연결하고, 실패에 대한 벌점을 최소화
7. **힌트는 답한 뒤에**: 사내 퀴즈에서도 정답의 단서(용어의 영문 약어, 보기 길이 차이, 문제 안의 핵심어 반복 등)가 문제에 드러나면 "떠올리기"가 일어나지 않음. 단서는 피드백 화면으로 옮기고, 답한 직후 정답·해설을 보여 주면 인출 연습과 즉각 피드백을 함께 얻을 수 있음
8. **여러 목소리로 듣기**: 고객 응대·전화 응대 교육의 예시 녹음도 한 강사의 목소리만 쓰면 학습자가 '그 사람의 말투'에 익숙해져 맞히는 몫이 생깁니다. 여러 사람의 목소리·말투·속도를 섞으면 현장의 다양한 고객에 미리 노출시킬 수 있습니다. 단, 근거가 된 말소리 연구(HVPT)의 '여러 화자 훈련이 더 낫다'는 결과는 대규모 재현 연구에서 효과가 아주 작게 나왔으므로, 큰 성과를 약속하기보다 손해 없는 설계 원칙 정도로 쓰고 효과는 따로 확인하는 것이 좋습니다
9. **출시 전 14일 파일럿**: 플레이의 비공개 테스트 조건(테스터 12명 이상이 14일 연속 참여)은 사내 교육의 파일럿 운영과 같은 구조입니다. 소수 학습자에게 '하루 한 화 × 14일'을 먼저 돌려 보고, 짧은 설문(좋았던 점·불편했던 점·계속할 의향)으로 고친 뒤 넓히면, 출시 조건도 채우고 개선 근거도 남습니다. 이 앱의 1~14화(히라가나 → 탁음·요음 → 인사·리액션·숫자, 보스전 2번)가 그 길이에 맞습니다
