**만 18세 이상 · 홈과 나(기록) 화면에 작은 배너 1개 · 광고 제거 판매 없음 · 보상형 광고 없음**으로 정한 구글 플레이 판을 실제로 올리는 순서입니다.

- 코드와 자동 빌드는 준비되어 있습니다. **[내가 할 일]** 표시가 붙은 단계만 직접 하시면 됩니다.

- 정책 내용은 2026년 10월에 확인했습니다. 출처는 맨 아래에 있습니다. 공식 문서에서 직접 확인하지 못한 내용은 **(확인 필요)**로 표시했습니다.

## 1. GitHub에 업로드 키 비밀번호 넣기 [내가 할 일]

**업로드 키란?** 플레이에 올리는 파일은 '업로드 키'로 서명해서 올립니다. 구글은 이 서명으로 '정말 개발자가 올린 파일인지' 확인한 다음, 구글이 보관하는 '앱 서명 키'로 다시 서명해 사용자에게 배포합니다(Play 앱 서명). 그래서 업로드 키를 잃어버리거나 새어 나가도 Play Console에서 **업로드 키 재설정**을 요청할 수 있습니다.

이 저장소의 자동 빌드는 업로드 키를 처음 한 번 직접 만들어, **비밀번호로 암호화한 파일**(`android/keystore/animimi-upload.p12`)로 저장소에 올립니다. 비밀번호는 GitHub Secrets에만 둡니다. 공개 저장소에 올라가도 비밀번호가 길고 무작위라면 열 수 없고, 설령 열리더라도 내 Play Console 계정 없이는 플레이에 아무것도 올릴 수 없습니다.

1. **비밀번호 정하기**: 25자 이상, 무작위로(비밀번호 관리자의 생성 기능 추천). 비밀번호 관리자나 안전한 곳에 꼭 적어 두세요. **채팅에는 붙여 넣지 마세요.**
2. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**
   - Name: `PLAY_UPLOAD_PASSWORD`
   - Secret: 정한 비밀번호 → **Add secret**
3. 다음에 main에 앱 변경이 올라가면 자동 빌드의 `play` 작업이 아래 일을 합니다. 기다리지 않고 바로 돌리려면 **Actions → "Android 앱 (APK·구글 플레이 AAB)" → Run workflow**에서 브랜치 **main**을 골라 실행합니다.
   - 업로드 키가 없으면 만들어서 main에 올림 (커밋 이름 `Add Google Play upload key …`)
   - 광고 ID를 아직 넣지 않았으면 **구글 시험용 광고**로 `animimi-play.aab`를 만듦
   - 그 빌드의 릴리스(`app-v1.0.N`)에 `animimi-play.aab`를 `animimi.apk`와 함께 올림
4. **AAB 받기**: https://github.com/hyogiman/jpnst/releases → 맨 위 릴리스 → Assets → `animimi-play.aab` (약 109MB, PC에서 받는 편이 편함)

> 비밀번호를 잃어버리면 키 파일을 열 수 없습니다. 그때는 키 파일을 지우고 새 비밀번호로 새 키를 만든 뒤, Play Console의 **앱 무결성(App integrity) → 앱 서명** 화면에서 업로드 키 재설정을 요청합니다(구글 처리에 며칠 걸림).

## 2. 플레이 개발자 계정 만들기 [내가 할 일]

주소: https://play.google.com/console/signup → **개인(Personal)** 계정

- **등록비**: 25달러, 한 번만 냅니다.
- **준비물**: 개발자용 Google 계정(앱 전용으로 새로 만드는 것을 권장), 신분증, 휴대폰 번호, 연락용 이메일, Android 10 이상의 실제 휴대폰
- **본인 인증**: 이름·주소가 신분증과 맞는지 확인합니다. 며칠 걸릴 수 있습니다.
- **기기 인증**: Play Console 웹 홈의 기기 확인 작업(Verify that you have access to an Android mobile device) → QR 코드 → 휴대폰에 **Play Console 앱**을 설치하고 계정 소유자로 로그인 → 확인. 루팅하지 않은 Android 10 이상 휴대폰이면 되고, 다른 사람의 휴대폰을 빌려도 됩니다(그 휴대폰 번호는 수집하지 않는다고 구글이 밝힘).

**공개되는 정보를 미리 확인하세요**

- 개발자 이름(직접 정함)과 **개발자 이메일은 스토어에 공개됩니다.** 개인 메일 대신 앱 문의용 메일을 새로 만드는 것을 권장합니다.
- 개인 계정은 인증한 실명이 스토어의 '개발자 정보'에 표시될 수 있습니다. 또 **유료 앱이나 인앱 결제로 돈을 받으면 주소까지 공개된다**는 보고가 많습니다 **(확인 필요 — 가입 화면의 공개 범위 안내를 꼭 읽으세요)**. 이번 앱처럼 광고만 있는 무료 앱은 플레이 결제를 쓰지 않습니다.
- 2023년 11월 13일 이후에 만든 개인 계정은 **4단계 비공개 테스트**를 통과해야 일반 공개를 신청할 수 있습니다.

## 3. 앱 만들기와 신고 [내가 할 일]

### 3-1. 앱 만들기

Play Console → **모든 앱 → 앱 만들기(Create app)**

| 칸 | 입력 |
|---|---|
| 앱 이름 | `アニ耳 - 애니 청해 일본어 180일` (listing-ko.md 1번) |
| 기본 언어 | 한국어 – ko-KR |
| 앱 또는 게임 | 앱 |
| 무료 또는 유료 | **무료** |
| 선언 | 개발자 프로그램 정책 · 미국 수출 법규 동의 |

> **무료로 낸 앱은 나중에 유료로 바꿀 수 없습니다**(공식 도움말). 나중에 돈을 받으려면 같은 앱 안의 인앱 상품을 쓰거나, 앱 ID가 다른 새 앱을 내야 합니다. 이번 결정(광고 제거 판매 없음)과는 맞지만 미리 알아 두세요.

### 3-2. 앱 콘텐츠 신고

Play Console → **정책 및 프로그램 → 앱 콘텐츠(App content)**. 모두 마쳐야 테스트 버전도 낼 수 있습니다.

| 항목 | 답 | 이유 |
|---|---|---|
| 개인정보처리방침 | `https://2nhyeok.kr/privacy/` | 광고 SDK가 있는 앱은 필수 |
| 앱 액세스 권한 | 모든 기능을 특별한 액세스 권한 없이 사용 가능 | 로그인·회원가입 없음 |
| 광고 | **예, 광고가 포함되어 있습니다** | 홈·나 화면 배너. 스토어에 '광고 포함'이 표시됨 |
| 콘텐츠 등급 | 설문 응답 (3-3) | |
| 타겟층 및 콘텐츠 | **만 18세 이상**만 선택 | 아래 '왜 18세 이상인가' 참고. 13세 미만이 대상이 아니므로 가족 정책은 해당 없음 |
| 뉴스 앱 | 아니요 | |
| 데이터 보안 | 3-4대로 | |

| 정부 앱 · 금융 기능 · 건강 앱 | 아니요 · 없음 · 없음 | |

| (나오면) 그 밖의 질문 | 사실대로 | |

**왜 18세 이상인가**: 앱의 음성은 구글 클라우드의 음성 합성(Chirp 3: HD)으로 만들었습니다. 구글 클라우드 서비스별 약관에는 생성형 AI 서비스를 18세 미만이 쓰는(쓸 가능성이 큰) 서비스와 함께 쓰지 못하게 하는 조항이 있습니다. 하지만 두 가지가 분명하지 않습니다. 하나는 Chirp 3: HD 음성 합성이 이 조항의 '생성형 AI 서비스'에 들어가는지이고, 다른 하나는 미리 만든 녹음 파일을 앱에 넣어 배포하는 것도 '함께 쓰는 것'인지입니다. 그래서 대상을 18세 이상으로 정해 조심스러운 쪽을 택했습니다. 개인정보처리방침 6번에도 18세 이상 대상이라고 적혀 있습니다.

### 3-3. 콘텐츠 등급 설문

- 이메일을 넣고, 카테고리는 **참고 자료, 뉴스 또는 교육(Reference, News, or Educational)**을 고릅니다.
- 앱 내용을 직접 찾아본 결과는 아래와 같습니다. 질문이 나오면 이대로 답하세요.
  - **거친 말**: 학습용 애니 대사에 くそ(젠장), てめえ(네놈), ばか(바보) 같은 가벼운 거친 말이 있습니다. 욕설·거친 말 질문에는 **'예(가벼운 수준)'**가 정직한 답입니다.
  - **폭력**: 묘사는 없습니다. 殺す(죽이다)는 단어 목록에만 한 번 나옵니다.
  - **담배·술**: '여기서 담배를 피우면 안 됩니다' 예문 1개, 그리고 외래어 유래를 설명하는 인문학 노트(タバコ·ビール)뿐입니다. 사용을 묘사하거나 권하지 않습니다.
  - **성적 내용·공포·도박·약물**: 없음
  - **사용자 간 소통·콘텐츠 공유, 위치 공유, 디지털 상품 구매**: 없음
- 등급은 설문 결과로 자동으로 정해집니다. 타겟층(18세 이상)과는 따로입니다.

### 3-4. 데이터 보안

앱 자체는 학습 기록을 어디에도 보내지 않습니다. 하지만 **Google 광고 SDK가 광고를 위해 데이터를 자동으로 수집해 Google에 보내므로**, 그 내용을 신고합니다. 애드몹 공식 'Google Play 데이터 공개' 안내를 따랐습니다.

| 질문 | 답 |
|---|---|
| 데이터를 수집하거나 공유하나요? | **예** |
| 전송 중 데이터가 암호화되나요? | **예** (광고 SDK는 TLS로 보냄) |
| 계정을 만들 수 있나요? | 아니요 (회원가입 없음) |
| 데이터 삭제를 요청할 방법을 제공하나요? | 아니요 (운영자가 보관하는 데이터가 없음) |

신고할 데이터 유형입니다. 네 가지 모두 **수집과 공유 둘 다 체크**하고, 일시적 처리는 '아니요', 수집은 '필수(사용자가 끌 수 없음)', 목적은 **광고 또는 마케팅 · 분석 · 사기 예방, 보안, 규정 준수**를 고릅니다.

| 분류 → 유형 | 실제 내용 |
|---|---|
| 위치 → **대략적인 위치** | IP 주소 (대략의 위치를 짐작하는 데 쓰일 수 있음) |
| 앱 활동 → **앱 상호작용** | 앱 실행, 탭, 광고 노출 등 |
| 앱 정보 및 성능 → **비정상 종료 로그**, **진단** | 비정상 종료 기록, 실행 시간 등 성능 정보 |
| **기기 또는 기타 ID** | 광고 ID, 앱 세트 ID |

- 학습 기록·백업 파일은 신고하지 않습니다. 기기 밖으로 보내지 않고, 백업 공유는 사용자가 직접 고른 곳으로 보내는 행동이기 때문입니다.
- 개인정보처리방침 3번에도 같은 내용이 있습니다.

## 4. 비공개 테스트 — 12명 × 14일 [내가 할 일 + 테스터]

**조건**: 테스터 **최소 12명**이 비공개 테스트에 **14일 연속** 참여(옵트인)한 상태여야 프로덕션 액세스를 신청할 수 있습니다. 조건을 채워도 신청 자격이 생길 뿐이고, 승인이 보장되지는 않습니다.

### 4-2. 비공개 테스트 만들기

1. **테스트 → 비공개 테스트(Closed testing)** → 기본 트랙(Alpha) → **트랙 관리**
2. **국가/지역** 탭: 대한민국
3. **테스터** 탭: **이메일 목록 만들기** → 테스터 Gmail 주소 입력 → 저장 → **'웹에서 참여' 링크 복사**
4. **출시** 탭 → **새 버전 만들기**
   - Play 앱 서명: **Google에서 생성한 앱 서명 키 사용**(기본값 그대로)
   - App Bundle: `animimi-play.aab` 업로드 (이때 우리 업로드 키가 등록됨)
   - 출시 노트: 예) `첫 테스트 버전입니다. 하루 한 화씩 진행해 보시고 불편한 점을 알려 주세요.`
   - 다음 → 저장 → **검토 후 출시**. 비공개 테스트도 구글 검토를 거칩니다(몇 시간~며칠).
5. 검토가 끝나면 테스터에게 링크를 보냅니다.

### 4-3. 테스터 모으기

- 중간에 빠지는 사람이 있어도 12명이 유지되도록 **15~20명**을 모으세요.
- 테스터 조건: Android 휴대폰과 Gmail 계정. 링크를 열어 **'테스터 되기'**를 누른 뒤 플레이 스토어에서 설치합니다.
- **교육 담당자로서 해 볼 만한 방법 — '14일 일본어 맛보기'**: 1~14화가 히라가나 전체(1~6화), 1주차 보스전(7화), 탁음·요음·촉음(8~10화), 인사말·리액션·숫자(11~13화), 2주차 보스전(14화)입니다. 비공개 테스트 기간과 정확히 맞으니 동료·지인에게 **"하루 한 화, 14일"** 챌린지로 제안하고, 끝날 때 짧은 설문(구글 설문지 3~5문항: 가장 좋았던 점, 불편했던 점, 이어서 할 생각이 있는지)을 받으세요. 테스트 조건도 채우고, 5단계 신청서에 쓸 **실제 피드백**도 생깁니다.

**테스터 안내문 예시** (복사해서 고쳐 쓰세요)


## 6. 애드몹 준비 [내가 할 일 + Claude]

**왜 이 단계를 뒤에 하나요?** 실제 광고 ID로 테스트하면 지인 테스터의 클릭이 '무효 트래픽'으로 잡혀 애드몹 계정이 제한될 수 있습니다. 그래서 비공개 테스트는 구글 시험용 광고로 하고, 실제 광고 ID는 프로덕션 출시 직전에 넣습니다.

### 6-1. 가입과 광고 단위 만들기

1. https://admob.google.com → Google 계정으로 시작 → 국가(대한민국)·시간대·결제 통화 선택 → 약관 동의
2. **앱 → 앱 추가**: 플랫폼 Android → "지원되는 앱 스토어에 앱이 등록되어 있나요?" → **아니요**(아직 출시 전) → 앱 이름 `アニ耳` → 추가
   - **앱 ID**를 받습니다: `ca-app-pub-0000000000000000~0000000000` 모양
3. 그 앱의 **광고 단위 → 광고 단위 추가 → 배너** → 이름(예: `home-me-banner`) → 만들기
   - **광고 단위 ID**를 받습니다: `ca-app-pub-0000000000000000/0000000000` 모양
4. **개인 정보 보호 및 메시지**: 대한민국에만 낸다면 지금은 만들지 않아도 됩니다(3-6 참고).

### 6-2. 광고 ID를 빌드에 넣기

두 ID는 **비밀값이 아닙니다**(출시된 앱 안에 그대로 들어감). 둘 중 편한 방법을 고르세요.

- **채팅으로 알려 주기** → Claude가 넣고 새 빌드를 만듭니다.
- **직접 넣기**: GitHub 저장소 → **Settings → Secrets and variables → Actions → Variables 탭 → New repository variable**
  - `ADMOB_APP_ID` = 앱 ID (`~`가 들어간 것)
  - `ADMOB_BANNER_ID` = 광고 단위 ID (`/`가 들어간 것)
  - 그다음 Actions에서 main으로 Run workflow → 새 `animimi-play.aab`

### 6-3. 지켜야 할 것

- **내 광고를 누르지 마세요.** 애드몹 정책 위반이고 계정이 정지될 수 있습니다. 내 휴대폰은 **애드몹 → 설정 → 테스트 기기**에 등록해 두면 실제 앱에서도 시험 광고만 보입니다. 광고 ID는 휴대폰의 **설정 → Google → 광고**에서 확인할 수 있습니다(기기마다 메뉴 이름이 조금 다름).
- 광고 내용 등급은 앱에서 **T(청소년)**까지로 제한해 두었습니다. 교육 앱에 어울리지 않는 성인 광고가 나오지 않게 하려는 것입니다.

### 6-4. 수익 받기

- 결제 정보(이름·주소)를 넣습니다. 수익이 **10달러**에 이르면 주소 확인용 **6자리 PIN이 국제 일반 우편**으로 옵니다. 추적 번호가 없고 도착까지 약 3주 걸리며, **4개월 안에** 입력하지 않으면 광고가 멈춥니다. 이 PIN은 본인 인증이 끝난 뒤에 보내집니다.
- 지급 기준액은 미국 달러 기준 **100달러**입니다. 원화로 받는 계정의 기준액은 애드몹 **결제** 화면에서 확인하세요. 매달 20일 잔액이 기준을 넘으면 지급됩니다.
- 세금 정보(미국 세금 양식 등) 제출 화면이 나오면 안내대로 냅니다 **(확인 필요 — 개인·한국 거주자 기준 안내를 따르기)**.
- **세금·겸업**: 광고 수익도 소득이므로 금액과 형태에 따라 종합소득세 신고 대상이 될 수 있습니다. 세무서(국세청 상담센터 126)나 세무사에게 확인하세요. 회사의 취업규칙에 겸업 관련 조항이 있는지도 확인해 두는 것이 좋습니다.

## 10. 나중에 정할 일 (지금은 하지 않아도 됨)

### 10-1. 직접 설치판(2nhyeok.kr/apk)을 계속 둘지

- **안드로이드 개발자 인증**: 2026년 9월 30일부터 브라질·인도네시아·싱가포르·태국에서, 인증된 개발자가 등록한 앱이 아니면 일반적인 방법으로 설치되지 않습니다. 구글은 2027년부터 전 세계로 넓힌다고 밝혔습니다. 한국의 날짜는 아직 따로 발표되지 않았습니다.
- 플레이 개발자는 Play Console에서 플레이 밖에서 배포하는 앱도 등록할 수 있습니다. 하지만 **직접 설치판의 서명 키는 저장소에 공개되어 있습니다.** 이 키를 등록하면 남이 같은 키로 만든 APK도 '내 앱'으로 인정될 수 있으므로 **등록하지 마세요.**
- 그래서 2027년 전에 둘 중 하나를 정해야 합니다.
  - **(a) 직접 설치판 중단 (권장)**: 플레이 판으로 옮기도록 안내만 남기기
  - **(b) 새 비공개 키로 바꾸기**: 이미 설치한 사람은 백업 → 삭제 → 다시 설치가 한 번 필요
- 광고 제거를 팔 계획이 생기면, 광고 없는 무료 직접 설치판과 웹판(2nhyeok.kr)이 있는 한 살 이유가 약하다는 점도 함께 고려하세요.

### 10-2. 광고 제거 판매

결정 근거는 [DESIGN.md의 '구글 플레이 판' 항목](DESIGN.md)에 적었습니다. 판다면 **별도 유료 앱보다 같은 앱의 1회 구매(인앱 상품)**가 낫습니다.

- 기록이 그대로 이어집니다.
- 평점과 리뷰가 나뉘지 않습니다.
- 빌드를 하나만 관리하면 됩니다.
- 새 앱을 만들면 비공개 테스트(12명 × 14일)를 다시 거쳐야 할 가능성이 큽니다 **(확인 필요)**.

어느 쪽이든 판매를 시작하면 결제 프로필이 필요하고, 주소 공개와 세금 신고 문제가 함께 생깁니다.
