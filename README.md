# アニ耳 (아니미미) — 애니 청해 일본어 180일

일본어를 **전혀 모르는 한국어 화자**가 6개월 동안 하루 한 화(20~30분)씩 공부해, **일본 애니메이션의 대사를 알아듣는 청해 기초**를 만드는 모바일 학습 웹앱입니다.

- 히라가나·가타카나부터 시작 (글자마다 한국어 기억법 · 기원 한자 · 음성 · 쓰기 연습)
- 모든 글자·단어·예문·대사에 **일본어 음성** — 구글 최신 음성, 남녀 목소리 4개를 섞어 씀. 설정에서 한 목소리만 골라 들을 수도 있고, 문제·카드의 **다른 목소리** 버튼으로 그 자리에서 바꿔 들을 수도 있음 (속도 조절, 애니 속도 1.25배 듣기). 녹음은 모두 일본어 음성 인식으로 받아 적어 **맞게 읽었는지 검사**한 것만 씀
- **매 화 마지막에 평가** (10문항, 70점 통과 · 90점 하나마루) — 통과해야 다음 화가 열림
- 문제에는 **가나만** 보여 주고, 한자·로마자는 답을 고른 뒤 정답 카드로 공개 (설정에서 힌트를 켤 수 있음)
- 주간 **보스전**, 챕터 **승급 시험**(F급 → S급), 스탬프 카드, 연속 학습, 레벨, 배지, 성장 그래프
- 틀린 것은 **간격 반복(SRS)** 으로 알맞은 날에 다시 출제
- **복습은 하나로** (복습 탭): 버튼 하나로 **20문항씩, 끝없이** 이어 풀기. 간격 반복 일정상 **복습할 때가 된 것을 먼저** 내고, 남는 자리는 지금까지 배운 단어·문법(예문·"예문 더 보기"까지)·애니 대사·장면 대화에서 아직 안 나온 것·오래 안 본 것·자주 틀린 것으로 채움. 종류는 골고루·단어·문법·예문·듣기 중에서 고름
- **문제 난이도** (설정·복습 탭): 보기 고르기 / 섞어 풀기(기본) / 주관식. 어려울수록 보기 없이 **일본어 자판으로 직접 쓰기**(가나로 쓰면 되고 한자로 바꾸지 않아도 정답. 자판이 없으면 로마자나 한글 자판으로 쳐도 가나로 바꿔 줌), 듣고 받아쓰기, 빈칸 직접 쓰기, 가짜 조각이 섞인 문장·단어 조각 맞추기, 뜻·소리를 떠올린 뒤 스스로 채점. 보기 문제도 소리가 비슷하거나 같은 주제의 말(きれい ↔ きらい·くらい)로 보기를 골라 헷갈리게 함
- 매 화 **인문학 한 스푼** — 언어·문화·철학·심리학으로 생각을 넓히는 짧은 읽을거리
- 문법마다 **자세히 보기** — "왜 그렇게 되는지"(어원·소리 변화·한국어 비교), 예문 더 보기(음성 포함), 비교·주의, 애니에서 쓰이는 모습

## 휴대폰에서 실행하기

### 방법 0. Android 앱으로 설치 (추천)
**내려받기: https://github.com/hyogiman/jpnst/releases/latest/download/animimi.apk** (항상 최신 버전)
설치 안내 페이지: **https://2nhyeok.kr/apk** (휴대폰 Chrome 앱 주소창에 `2nhyeok.kr/apk` 입력 — 문제 해결 방법 포함)

1. 휴대폰 Chrome으로 위 주소를 열면 `animimi.apk`가 내려받아집니다. (웹 앱의 **나 → 휴대폰 앱으로 설치** 버튼도 같은 주소)
2. 내려받은 파일을 엽니다. 처음 한 번은 **"출처를 알 수 없는 앱 설치"** 를 허용해야 합니다. (Chrome 또는 내 파일 앱 → 허용 → 뒤로)
3. **설치 → 열기**. 홈 화면에 `アニ耳 일본어` 아이콘이 생깁니다.

- 앱 안에 모든 화면·음성(목소리 4개, 약 124MB)·글꼴이 들어 있어 **인터넷 없이도** 학습할 수 있습니다. 설치 파일은 약 140MB입니다.
- 새 버전이 나오면 같은 주소에서 받아 **덮어 설치**하면 학습 기록이 그대로 유지됩니다. (앱을 삭제하면 기록도 지워지니 나 → 백업 내보내기를 가끔 해 두세요)
- 앱은 인터넷에 연결되어 있을 때 6시간에 한 번 GitHub Releases의 최신 버전을 확인하고, 새 버전이 있으면 **홈 화면 맨 위에 안내**합니다. 나 → 설정 → **앱 버전**에서 지금 버전을 보고 직접 확인할 수도 있습니다. (1.0.2 이하 버전에는 이 기능이 없으니 한 번은 직접 내려받아 주세요)
- 웹(2nhyeok.kr)에서 하던 기록 옮기기: 웹의 **나 → 백업 내보내기** → 앱의 **나 → 백업 불러오기**에서 그 파일 선택
- 앱에서는 휴대폰 뒤로 가기 버튼으로 창 닫기 → 레슨 그만하기 확인 → 홈 → 앱 종료 순서로 동작하고, 백업은 공유 창(드라이브·카카오톡 등)으로 보냅니다.
- Play 스토어 밖에서 받은 앱이라 설치할 때 Play 프로텍트가 앱을 검사하겠냐고 물을 수 있습니다. 검사 후 설치하면 됩니다.
- **다운로드가 100%에서 멈추면**: 카카오톡·Claude 같은 다른 앱 안의 브라우저(맞춤 탭)에서는 "그래도 다운로드할까요?" 확인 창이 가려져 멈출 수 있습니다. 알림창이나 내 파일 → 다운로드에 파일이 있는지 보고, 없으면 Chrome 앱에서 다시 받으세요.
- 삼성 갤럭시에서 "자동 차단 기능에 의해 차단됨"이 뜨면 설정 → 보안 및 개인정보 보호 → 자동 차단 기능을 잠시 끄고 설치합니다.
- **iPhone**은 앱 파일 설치가 불가능하므로 아래 방법 1(Safari → 홈 화면에 추가)을 쓰세요.

**APK가 만들어지는 방식**: `main`에 앱 파일이 바뀌어 올라오면 GitHub Actions(`.github/workflows/android.yml`)가 [Capacitor](https://capacitorjs.com/)로 Android 앱을 빌드해 GitHub Releases에 올립니다. 버전 번호(versionCode)는 빌드마다 커지므로 항상 덮어 설치할 수 있습니다.

> **서명 키에 관한 주의**: 업데이트가 덮어 설치되려면 모든 APK가 같은 키로 서명되어야 합니다. 저장소 Secrets를 설정하지 않아도 바로 쓸 수 있도록 개인 배포용 키(`android/keystore/animimi-sideload.jks`, 비밀번호 `animimi-sideload`)를 저장소에 넣어 두었습니다. 공개 저장소이므로 누구나 같은 키로 서명한 APK를 만들 수 있다는 뜻이니, **APK는 반드시 위 Releases 주소에서만 받으세요.** 키를 비공개로 바꾸려면 새 키를 만들어 Settings → Secrets and variables → Actions에 `ANIMIMI_KEYSTORE_B64`(키 파일을 base64로 인코딩한 값), `ANIMIMI_KEYSTORE_PASSWORD`, `ANIMIMI_KEY_ALIAS`, `ANIMIMI_KEY_PASSWORD`를 넣으면 됩니다. 단, 키가 바뀌면 이미 설치한 앱은 한 번 삭제 후 다시 설치해야 합니다(그 전에 백업 내보내기).

직접 빌드하려면 (Android SDK·JDK 21 필요):
```bash
npm ci
npm run app            # www/ 생성 + android 프로젝트에 복사
cd android && ./gradlew assembleRelease   # → app/build/outputs/apk/release/app-release.apk
```

### 구글 플레이 판 (출시 준비 중)
같은 코드로 만든 구글 플레이용 앱 번들(AAB)입니다. 출시 순서는 **[docs/PLAY-STORE.md](docs/PLAY-STORE.md)**, 스토어에 넣을 글과 그림은 **[store/](store/listing-ko.md)**에 있습니다.

- **광고**: 홈과 나(기록) 화면 아래에 Google AdMob 배너 1개. 레슨·평가 중이나 창(라이선스 등)이 열려 있을 때는 숨김. 광고 제거 판매와 보상형 광고는 없음
- **대상**: 만 18세 이상. 광고 내용 등급은 T(청소년)까지로 제한
- **개인정보처리방침**: https://2nhyeok.kr/privacy/ (`privacy/index.html`). 유럽 등 동의가 필요한 지역에서는 구글 동의 화면(UMP)이 뜨고, 나 → 설정의 **광고 개인정보 설정**에서 바꿀 수 있음
- 플레이 판에서는 GitHub 새 버전 확인을 끔(플레이가 업데이트함). 설정에 **개인정보처리방침**·**오픈소스 라이선스** 메뉴가 생김
- **빌드**: `ANIMIMI_STORE=play node tools/build-app.js`가 `www/index.html`에 플레이 판 표시와 광고 설정을 넣음. 자동 빌드의 `play` 작업이 GitHub Secrets의 `PLAY_UPLOAD_PASSWORD`로 업로드 키(`android/keystore/animimi-upload.p12`, 이 비밀번호로 암호화)를 처음 한 번 만들고, `animimi-play.aab`를 서명해 같은 릴리스에 올림. 광고 ID는 저장소 Variables의 `ADMOB_APP_ID`·`ADMOB_BANNER_ID`(없으면 구글 시험용 광고)
- 직접 설치판과 앱 ID는 같지만 서명이 달라 서로 덮어 설치되지 않음 → 옮길 때는 백업 내보내기 → 삭제 → 플레이에서 설치 → 백업 불러오기

### 방법 1. GitHub Pages + 도메인 `2nhyeok.kr` (현재 설정)
앱은 `main` 브랜치 루트에 있고, `CNAME` 파일에 `2nhyeok.kr`이 지정되어 있습니다.
1. 저장소 **Settings → Pages** 에서 Source를 `Deploy from a branch`, 브랜치 `main`, 폴더 `/ (root)`로 저장합니다.
2. 같은 화면의 **Custom domain**에 `2nhyeok.kr`이 들어가 있는지 확인합니다.
3. 도메인 업체(DNS 관리)에서 아래 레코드를 추가합니다.

   | 호스트 | 유형 | 값 |
   |---|---|---|
   | `@` | A | `185.199.108.153` |
   | `@` | A | `185.199.109.153` |
   | `@` | A | `185.199.110.153` |
   | `@` | A | `185.199.111.153` |
   | `www` | CNAME | `hyogiman.github.io` |

   (IPv6를 쓰려면 AAAA 레코드 `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`)
4. DNS가 반영되면(보통 몇 분~최대 48시간) Pages 화면에서 **Enforce HTTPS**를 켭니다.
5. 휴대폰에서 `https://2nhyeok.kr`을 열고 **홈 화면에 추가**하면 앱처럼 전체 화면으로 실행되고, 한 번 연 뒤에는 오프라인에서도 동작합니다.
   - iPhone(Safari): 공유 버튼 → 홈 화면에 추가
   - Android(Chrome): 메뉴 → 홈 화면에 추가 / 앱 설치

> 저장소가 비공개(private)라면 요금제에 따라 Pages 사용이 제한될 수 있습니다. 설정 방법은 GitHub 문서 "Managing a custom domain for your GitHub Pages site"를 참고하세요.

## 음성
- 기본은 **녹음 음성**입니다. 모든 가나·단어·예문·대사(섞어 듣기용 2,666개 + 목소리 고르기용 7,964개, 서로 다른 소리 8,202개, 약 124MB)를 **구글 Cloud Text-to-Speech의 최신 음성(Chirp 3: HD)** 으로 미리 만들어 `audio/`에 넣어 두었습니다. 휴대폰에 일본어 음성이 없어도, 앱 안 브라우저에서도 같은 소리가 나고, 한 번 받으면 오프라인에서도 재생됩니다. 듣는 것은 구글에 접속하지 않으므로 몇 번을 들어도 비용이 들지 않습니다.
- **목소리 네 개를 섞어 씁니다**: 여성 **Despina·Sulafat**, 남성 **Algenib·Fenrir** (일본어 Chirp 3: HD 목소리 30개(여성 14·남성 16)를 같은 말로 만들어 학습자가 직접 듣고 고름).
  - 글자(가나): Despina 한 목소리로, 0.7배속으로 또렷하게 (예전에는 0.5배속. 어려운 글자 21개를 네 목소리·세 속도로 만들어 받아 적어 보니 0.5배속이 오히려 잘못 읽힌 비율이 조금 높았음 — 맞게 받아 적힌 비율 0.5배속 58.6%, 0.7배속 62.8%, 0.85배속 62.5%)
  - 단어: 네 목소리에 고르게 나눔. 소리 구별 짝(かき·かぎ 등)은 두 단어를 같은 목소리로
  - 예문·애니 대사: 남자 말투(おれ·お前·ぞ 등)는 남성, 여자 말투(わよ·かしら 등)는 여성, 나머지는 고르게
  - 장면 대화: 등장인물의 성별에 맞춰 인물마다 목소리 하나를 고정
  - 이유: 한 목소리로만 공부하면 그 목소리에 익숙해져서 맞히는 몫이 생깁니다(목소리 친숙성 효과). 그래서 처음부터 여러 목소리를 섞어 처음 듣는 목소리에도 대비합니다. 여러 화자 훈련의 이점은 원 연구(HVPT)에서 보고됐지만 대규모 재현 연구에서는 효과가 작게 나와, '반드시 더 낫다'기보다 손해 없는 선택으로 보는 것이 정확합니다(자세한 근거는 docs/DESIGN.md).
- **목소리 고르기**: **나 → 설정 → 목소리**에서 섞어 듣기(기본) 대신 Despina·Sulafat·Algenib·Fenrir 중 하나를 고르면, 장면 대화를 뺀 모든 음성(글자·단어·예문·애니 대사)이 그 목소리로 나옵니다. 장면 대화는 인물을 구분해야 해서 인물마다 정한 목소리를 그대로 씁니다. 그래서 장면 대화를 뺀 모든 항목을 네 목소리로 하나씩 더 녹음해 목소리별 묶음(`audio/pack2-sulafat-xxxx.mp3` 등)에 넣었고, 기본 묶음에 이미 있는 소리는 같이 씁니다. 문법 자세히 보기의 "예문 더 보기"(580개)는 앱 용량 때문에 섞어 듣기용 한 목소리로만 만들었습니다.
- **다른 목소리 버튼**: 문제·단어 카드·글자 카드·정답 카드에 "다른 목소리" 버튼이 있어, 누를 때마다 다음 목소리 녹음으로 들려주고 그 목소리 이름을 보여 줍니다(방금 들은 녹음과 같은 목소리는 건너뜀). 한 목소리의 발음이 귀에 잘 안 들어올 때 다른 화자로 확인할 수 있어요.
- **읽기는 후리가나와 똑같이**: 한 글자 한자(何·方·上 등 읽기가 여러 개인 것)는 후리가나로 바꿔 넣고, 두 글자 이상 한자는 일본어 요미가나 지정 기능으로 읽기를 지정합니다. 이 지정이 실제로 반영되는지는 今日(きょう/こんにち)·日本(にほん/にっぽん) 등 12건을 소리 모양 비교(MFCC + DTW)로 확인했습니다(11건 반영). 지정이 무시될 때를 대비해, 사전(Open JTalk)의 기본 읽기가 후리가나와 다른 말(日本→にほん, 九時→くじ, 辛い→からい, 一回→いっかい 등 20개 낱말)은 한자 대신 가나로 넣습니다.
- **맞게 읽은 소리만 (2026-10 추가)**: 구글 음성은 같은 입력도 만들 때마다 조금씩 다르게 읽고, 가끔은 아예 다른 소리로 읽습니다. "큐·뷰 같은 소리를 잘못 읽어 알고도 틀린다, つ도 이상한 목소리가 꽤 있다, した(아래)는 다른 말처럼 들린다"는 학습자 피드백을 받고 예전 녹음을 모두 일본어 음성 인식으로 받아 적어 보니, した 녹음 5개(섞어 듣기 + 네 목소리) 중 4개가 じゃ·さあ·あっ으로(고르는 데 쓰지 않은 Whisper로도 じゃあ·じゃ·웃음소리), つ 5개 중 4개가 あ·え로, こうこう 5개 중 4개가 こう로 받아 적혔고, Sulafat의 びゅ는 "비유(美由)"로 받아 적혔습니다. 예전에는 "맑기"로만 골라서 맞게 읽었는지는 보지 않았기 때문입니다. 지금은 후보마다 앱에 넣을 최종 소리를 음성 인식 두 가지(ReazonSpeech 일본어 모델·SenseVoice, `tools/asr_verify.py`)로 받아 적어, 기대 읽기와 맞는 후보 중에서만 고릅니다.
  - 박(모라) 단위로 비교합니다. 단어·문장은 장음·촉음까지 구별해 소리 구별 문제의 짝이 뒤바뀐 녹음도 잡습니다(예전 녹음에서는 Despina의 ここ가 こうこう로 받아 적혔음). 가나 한 글자는 인식기가 キュ를 "九(きゅう)"처럼 늘려 적는 버릇이 있어 장음 차이만 넘어갑니다.
  - 맞는 후보가 없으면 같은 입력으로 몇 번 더 만들고, 그래도 없으면 입력을 바꿔(마침표 붙이기·가나·가타카나·한자 그대로, 글자는 다른 속도) 만들어 봅니다.
  - 한 글자 한자를 가나로 바꿔 넣은 문장에서는 구글 음성이 조사 は·へ를 "하·헤"로 읽는 일이 있었습니다(彼は → "카레하", 妹は絵が → "이모토하에가", ジムへ → "지무헤"). 받아 적은 결과에서 조사 자리가 ハ·ヘ로 들리면 틀린 것으로 보고, 한자 그대로 넣은 후보에서 다시 고릅니다.
  - 숨소리를 자르는 규칙에 약한 첫소리가 잘린 경우가 있어(Fenrir의 ほっとする → "とする", よふかし → "ふかし"), 받아 적기가 틀리면 앞을 덜 자른 소리로 다시 검사합니다. 말하는 도중에 뚝 끊겨 온 녹음(약 2%)은 끝의 페이드가 마지막 소리(ます의 す 등)를 깎지 않도록 무음을 덧붙이고, 고를 때도 감점합니다.
  - **첫소리가 잘린 채 온 녹음**: 구글 음성은 후보의 약 7%를 말소리 한가운데서 시작하는 소리로 보냅니다(정상인 후보는 대개 최대보다 60dB 넘게 낮은 무음으로 시작). 예를 들어 Despina의 つよい는 앱에 들어 있던 녹음이 つ의 마찰음 도중부터 시작해 す처럼 들릴 수 있었습니다(같은 입력으로 만든 다른 후보들은 대부분 정상). 음성 인식은 이런 녹음도 대개 맞게 받아 적고, 맑기 점수는 오히려 높게 쳐서 걸러지지 않았습니다. 앱에 든 녹음 중 566개(5.3%)가 이랬습니다. 지금은 처음 5ms가 최대보다 40dB 낮은 소리보다 크면 '첫소리 잘림'으로 보고, 첫소리가 온전한 후보를 먼저 고르며, 맞게 읽은 후보가 모두 이러면 더 만듭니다.
  - **앱에 들어가는 MP3 그대로 한 번 더**: 압축 전 소리로는 맞았는데 MP3로 압축한 뒤에는 틀리게 받아 적히는 아슬아슬한 녹음이 약 1% 있었습니다(대개 약하게 난 첫 박: はやくしろ → やくしろう). 그래서 고른 후보를 앱에 넣을 MP3로 압축해 다시 받아 적고, 맞지 않으면 다음 후보로 넘어갑니다.
  - **세 번째 인식기 (가나·소리 구별 짝)**: 가나 한 글자는 두 인식기가 비슷한 소리를 함께 놓칠 때가 있어(섞어 듣기용 ぱ가 か로, ぎょ가 きょう로, Sulafat의 ぜ가 せ로 받아 적힘), 고르는 데 쓰지 않던 Whisper small로도 받아 적어 **두 인식기 중 하나와 Whisper가 모두 맞게 적은 녹음**을 고릅니다. 지금 앱에 든 녹음이 이 조건을 넘으면 그대로 두고, 아니면 후보 중에서 다시 고르고, 그래도 없으면 같은 속도로 몇 개 더 만들어 봅니다. 소리 구별 짝(かき·かぎ 등)과 Whisper 표본에서 다르게 적힌 단어도 같은 방식으로 다시 골랐습니다.
  - **조사 は·へ를 '하·헤'로 읽은 문장 (Whisper로 찾음)**: 두 인식기는 받아 적은 は를 발음으로 바꿀 때 늘 조사 '와'로 읽어 버려서, 구글 음성이 조사를 '하'로 읽어도 놓칠 때가 있었습니다. 한자를 가나로 바꿔 넣은 입력으로 고른, 조사 は·へ가 있는 문장 526개를 Whisper로 받아 적어 보니 34개가 다르게 적혔고(どこかへ行きたい → "どこか兵器隊", 京都へ行きました → "京都兵きました", お前は敵じゃない → "お前派…", 象は鼻が長い → "増波は…"), 한자 그대로 넣은 입력부터 더 만들어 다시 골라 30개는 세 인식기가 모두 맞게 적습니다. 남은 4개는 판정 쪽 한계입니다(Whisper가 うち를 家로 적으면 발음 변환이 いえ로 읽음 등).
  - 결과 (앱에 든 MP3 그대로, 예전과 같은 두 인식기·같은 판정 기준): 예전 녹음 **93.4%**(10,050개 중 9,388개) → 지금 **99.6%**(10,630개 중 10,590개). 가나 한 글자 67.7% → **98.6%**, 단어 96.6% → 99.6%, 소리 구별 짝 91.4% → 100%, 문장 96.8% → 99.9%.
    - 세 번째 인식기 Whisper로 같은 표본 2,237개를 받아 적으면 73.2% → 94.6%(가나 57.5% → 94.8%). 가나 1,105개 중 **세 인식기 중 둘 이상이 맞게 적은 녹음은 50.4% → 93.9%**, 셋 다 다르게 적은 녹음은 269개 → 5개입니다. 다만 이제 Whisper도 가나·짝 등을 고르는 데 썼으므로 이 숫자는 '세 인식기가 동의하는 정도'입니다. Whisper를 고르는 데 쓰지 않은 단어·문장 901개만 보면 97.9% → 99.2%였습니다.
    - した 다섯 녹음은 이제 ReazonSpeech와 Whisper가 모두 した(下)로 받아 적고(SenseVoice도 셋은 下. 예전에는 넷이 じゃ·さあ·あっ), つ는 다섯 모두 つ(예전: 넷이 あ·え), Sulafat의 びゅ는 ビュー(예전: 美由), Despina의 こうこう는 高校(예전: こう·ここ)로 받아 적힙니다. 첫소리가 잘린 녹음은 566개 → 약 20개(후보가 모두 잘린 것 등).
    - 이번에 바뀐 녹음은 960개 항목(서로 다른 소리 673개: 가나 259·단어 468·짝 13·문장 220 항목)이고, 바뀐 것은 모두 두 인식기로, 표본에 든 것은 Whisper로도 다시 받아 적어 위 숫자에 반영했습니다.
  - 한계: 음성 인식도 틀립니다. 두 인식기 모두 다르게 적는 녹음이 40개(0.4%) 남았는데, 대부분은 인식기의 버릇입니다 — 혼자 있는 ん을 늘 うん으로 적음(10개), 흔한 말 쪽으로 끌려감(よやく → ようやく, ココア → ここは, シーン → 新, いう → ゆう, ううん → うん). いいんちょう(院長으로 들림)처럼 실제로 애매할 수 있는 것도 있습니다. 가나 중에는 りゃ·りゅ·ぎゃ·びゃ·フォ·ウェ 등 67개가 세 인식기 중 둘을 넘지 못했는데, Whisper가 りゅ를 牛, ぎゃ를 きゃ, びゃ를 いや로 적는 등 이 소리들은 인식기끼리도 엇갈립니다. 끝내 맞는 후보를 찾지 못한 녹음은 가장 덜 틀린 후보를 씁니다(목록은 생성기가 마지막에 출력). 높낮이(악센트)·억양은 검사하지 못하고, 사람이 1만여 개를 모두 들어 본 것은 아닙니다 — 이상하게 들리는 녹음을 알려 주시면 그 항목만 다시 고를 수 있습니다(`--redo`).
- **그중 가장 또렷한 소리로**: 맞게 읽은 후보가 여럿이면 가장 또렷한 것을 고릅니다(글자 4번·단어 3번·문장 2번 만들기). 기준은 ① 성대 울림이 뚜렷한 비율(속삭이는 후보 거르기)과 ② 맑기(조화음 대 잡음비)입니다. 처음에는 맑기만 봤는데, 맑기는 울린 부분만 보고 재기 때문에 거의 속삭이고 잠깐만 울린 소리가 오히려 높게 나와 "ハ가 숨소리처럼 들린다"는 피드백을 받고 고쳤습니다. 글자는 히라가나·마침표 붙인 표기로도 후보를 더 만들고(は·へ는 조사 わ·え로 읽힐 수 있어 히라가나 제외), 모두 흐리거나 속삭이면 몇 번 더 만듭니다.
  - 남성 목소리(Algenib·Fenrir)는 목소리 결 자체가 낮고 거칠어, 여러 번 만들어도 단어·문장의 울림이 여성 목소리보다 적습니다. 숨소리처럼 들리는 게 거슬리면 **설정 → 목소리**에서 여성 목소리(Despina·Sulafat)를 고르세요.
- 96kbps MP3(48kbps에서 생기던 고음 손상 제거). 앞뒤는 말소리 바로 앞(0.08초, 글자는 0.12초)·뒤(0.18초)까지만 남깁니다. 구글 음성은 말하기 전에 작은 숨소리·잡음을 넣을 때가 있어(천천히 읽는 글자는 0.6~1.4초), 이것을 남기면 누른 뒤 1초쯤 쉬었다가 소리가 났습니다. 숨소리가 기준을 넘나들며 말소리 앞에 이어 붙는 경우도 있어, 분명한 말소리가 시작되기 0.15초(글자 0.3초) 전보다 앞은 숨소리로 보고 자릅니다.
- **나 → 설정 → 음성 방식**에서 "기기 음성"으로 바꾸면 휴대폰 내장 음성(iPhone의 Kyoko 등)을 씁니다(웹 버전에서만). 이때 소리가 안 나면:

- 콘텐츠를 고친 뒤 음성을 다시 만들려면:
  ```bash
  pip install "numpy<2" lameenc pyopenjtalk-prebuilt sherpa-onnx miniaudio
  # 발음 검사용 음성 인식 모델 두 개 (sherpa-onnx 배포 파일, 약 1GB). miniaudio는 고른 녹음을 MP3로 압축했다가 다시 풀어 검사할 때 씀
  mkdir -p /tmp/asr-models && cd /tmp/asr-models
  for m in sherpa-onnx-zipformer-ja-reazonspeech-2024-08-01 sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2025-09-09; do
    curl -L https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/$m.tar.bz2 | tar xj; done
  cd -
  node tools/audio-texts.js > /tmp/audio-texts.json
  GOOGLE_TTS_KEY=<API 키> python3 tools/make-audio-google.py /tmp/audio-texts.json --cache /tmp/gtts-cache --asr /tmp/asr-models --report /tmp/gtts-report.json
  # Claude 클라우드 환경에서는 키를 네트워크 시크릿으로 두고 키 없이 실행
  python3 tools/make-audio-google.py /tmp/audio-texts.json --proxy-key --cache /tmp/gtts-cache --asr /tmp/asr-models
  ```

  - 세 번째 인식기까지 쓰려면 Whisper small 모델(`sherpa-onnx-whisper-small`, 같은 배포 페이지, 약 1.3GB)을 더 받아 두고 `--whisper /tmp/asr-models/sherpa-onnx-whisper-small`을 붙입니다. 가나 한 글자 전부와 `--redo`로 준 단어·소리 구별 짝에 쓰입니다(Whisper는 느려서 문장에는 쓰지 않음).
  - API 키: Google Cloud 콘솔에서 Cloud Text-to-Speech API를 사용 설정하고 만든 키. **Text-to-Speech API로만 제한**하고, **저장소에는 절대 넣지 마세요.**
  - Claude 클라우드 환경에서 만들 때는 대화창에 키를 붙여 넣지 말고, 환경 설정 → **네트워크 시크릿**에 넣습니다: 시크릿 유형 **Bearer**, 허용된 웹사이트 `texttospeech.googleapis.com`, 사용자 지정 헤더 이름 `X-Goog-Api-Key`·접두사 빈칸·값에 키. 그러면 이 주소로 나가는 요청에만 키가 붙고, 키는 작업 공간에 들어오지 않습니다(`--proxy-key`).
  - 비용: 섞어 듣기용을 한 번 만드는 데 약 3만 1천 자, 목소리 고르기용까지 모두 만들면 약 11만 3천 자(여러 번 만들어 고르는 것 포함, 2026년 10월 실제 생성 기준). 발음 검사(`--asr`)로 전부 다시 고른 작업은 대부분 캐시를 다시 써서 요청 약 5,800건·2만 9천 자였습니다(가나 0.7배속 새로 만들기, 문법 '예문 더 보기' 새 녹음, 맞는 후보가 없을 때 더 만든 것 포함). 그 뒤 첫소리 잘림·MP3 검사·세 번째 인식기로 다시 고르는 데 요청 약 1,000건·6천 4백 자가 더 들었습니다. Chirp 3: HD는 한 달 100만 자까지 무료입니다([구글 가격표](https://cloud.google.com/text-to-speech/pricing), 2026년 10월 확인).
  - `--cache`를 쓰면 이미 만든 소리는 다시 요청하지 않아, 문장 몇 개를 고쳤을 때는 그 문장만 비용이 듭니다. `--dry`로 앱 파일을 건드리지 않고 시험할 수 있습니다.
  - 캐시가 없는 새 작업 공간에서도: `tools/audio-manifest.json`에 녹음마다 만든 조건(목소리·입력·읽기 지정·속도·횟수·자르기 방식)의 서명이 있어, 조건이 같은 소리는 지금 묶음에서 그대로 꺼내 쓰고 바뀐 항목만 요청합니다.
  - 요청 속도: Chirp 3: HD의 기본 한도는 프로젝트당 **분당 200건**이라([구글 할당량 문서](https://cloud.google.com/text-to-speech/quotas)) 분당 150건으로 묶어 보냅니다(`--rpm`). 목소리 고르기용까지 전체를 처음 만들면 요청이 약 2만 4천 건이라 분당 180건(`--rpm 180`)으로 2시간 남짓 걸립니다. `--asr`를 쓰면 후보마다 받아 적는 데 CPU 시간이 들어, 4코어 컴퓨터에서 1만여 개를 다시 고르는 데 2시간 반쯤 걸렸습니다. `--whisper`까지 쓰면 글자 녹음을 모두 세 번째 인식기로 확인하므로, 742개 소리를 다시 고른 작업이 1시간 10분쯤 걸렸습니다. 한도에 걸려도(429) 잠시 쉬었다가 이어 갑니다.
- 인터넷·API 키 없이 만드는 방법(이전 음성): `tools/make-audio.py`는 VOICEVOX(VOICEVOX:冥鳴ひまり·玄野武宏)로 같은 형식의 음성을 만듭니다. 쓰려면 VOICEVOX core 0.15와 ONNX Runtime 1.13.1이 필요하고(파일 맨 위 설명 참고), 해당 캐릭터의 크레딧을 앱에 표시해야 합니다.
- 묶음 파일 이름에 내용 해시가 붙어(`pack0-1a2b3c4d.mp3`) 다시 만들면 휴대폰도 새 음성을 받습니다.

## 복습과 문제 난이도
- **복습 탭에는 복습이 하나**: 예전의 오늘의 복습·누적 복습·무작위 청해 연습·약점 집중 훈련을 하나로 합쳤습니다(2026-10). "복습 시작"을 누르면 20문항이 나오고, 끝나면 "한 세트 더"로 계속 이어 풉니다.
  1. **복습할 때가 된 것 먼저**: 간격 반복 일정상 오늘 다시 볼 때가 된 항목(복습 탭 맨 위 숫자)을 오래 밀린 것부터 냅니다. 이 문항은 맞히면 기억 단계가 올라 간격이 1 → 2 → 4 → 7 → 14 → 30 → 60일로 늘고, 틀리면 단계가 내려가 다음 날 다시 나옵니다. 20개가 넘게 밀려 있으면 한 세트가 모두 이것으로 채워집니다.
  2. **남는 자리는 배운 것 전체에서**: 아직 안 나온 것 → 오래전에 나온 것 → 자주 틀린 것 순서로 골라 배운 것 전체를 돌아가며 냅니다. 문법은 본문 예문과 "예문 더 보기"를 모두 써서, 빈칸(문법의 핵심 형태·조사)·문장 배열·문장 뜻·문법 뜻·듣고 받아쓰기로 나옵니다. 이 문항은 틀렸을 때만 다음 날 복습에 다시 나오게 하고, 맞혔다고 간격을 늘리지는 않습니다(일정보다 일찍 본 것이라서).
  3. **종류**: 골고루(단어 8 · 문법 7 · 듣기 4 · 약한 글자 1의 비율) · 단어 · 문법·예문(애니 대사 포함) · 듣기(모든 문항을 듣기 문제로, 장면 대화·소리 구별 포함). 고른 종류에 맞는 "복습할 때가 된 것"만 먼저 나오고, 나머지는 다른 종류를 고르거나 골고루에서 나옵니다.
  4. 아래 **기억 단계** 카드에서 단계별 항목 수를 보고, "자주 틀리는 항목"을 펼쳐 볼 수 있습니다. 자주 틀린 항목은 따로 훈련하지 않아도 다음 날 복습과 세트 고르기에서 먼저 나옵니다.
- **문제 난이도**(나 → 설정, 복습 탭에서도 바꿀 수 있음, 레슨·평가·시험·복습 모두에 적용)
  - 보기 고르기: 4지선다. 보기는 소리가 비슷한 말·같은 한자·같은 주제의 말로 골라 헷갈리게 하되, 뜻이 겹치거나 바꿔 써도 맞는 말(へ/に 등)은 빼서 정답이 둘이 되지 않게 했습니다.
  - 섞어 풀기(기본): 절반쯤을 직접 쓰기·받아쓰기·조각 맞추기·떠올리기로.
  - 주관식: 보기를 거의 없앱니다. 평가·보스전·시험에서는 스스로 채점 대신 직접 쓰기로 나옵니다(통과 기준 70점은 그대로).
- **직접 쓰기 = 일본어 자판**: 휴대폰·PC에 일본어 자판을 추가해 가나로 쓰면 됩니다. 한자로 바꾸지 않아도 정답이고, 한자로 바꿔도 맞게 채점합니다. 입력칸 아래 "일본어 자판이 없나요?"를 누르면 설치 방법이 나옵니다.
  - 안드로이드(Gboard): 자판 위 설정(톱니바퀴) → 언어 → 키보드 추가 → 일본어 → 12키(가나를 밀어서 입력) 또는 QWERTY(로마자를 치면 가나로). 지구본 버튼이나 스페이스바 길게 누르기로 바꿈 ([Gboard 고객센터](https://support.google.com/gboard/answer/7068494?hl=ko&co=GENIE.Platform%3DAndroid))
  - 갤럭시(삼성 키보드): 설정 → 일반 → 삼성 키보드 설정 → 언어 및 키보드 형식 → 입력 언어 관리 → 일본어 내려받기 (안드로이드 11·12 이후 기준, 기종에 따라 다를 수 있음)
  - 아이폰: 설정 → 일반 → 키보드 → 키보드 → 새로운 키보드 추가 → 일본어 → 가나 또는 로마자. 지구본 버튼으로 바꿈 ([Apple 사용 설명서](https://support.apple.com/guide/iphone/add-or-change-keyboards-iph73b71eb/ios))
  - 자판이 없을 때를 위한 보조 입력: 로마자로 치면 가나로 바뀌어 미리 보이고(shi→し, tsu→つ, kk→っ, nn→ん, -→ー), 한글 자판으로 바꾸지 않고 쳐도 자판 글쇠로 되돌려 바꿉니다(노ㅑ → し). 일본어 자판의 전각 영문(ｓｈｉ)·반각 가타카나(ｼｺﾞﾄ)도 보통 글자로 바꿔 봅니다.
- **채점**: 장음 표기(こうひい ↔ コーヒー), 조사 は·へ·を를 소리대로 わ·え·お로 쓴 것, では/じゃ, 변환 후보에서 같은 소리의 다른 한자를 고른 것(ちかい: 近い ↔ 誓い)은 맞음으로 치고 바른 표기를 알려 줍니다. 길이·촉음·탁음이 다르면 틀림입니다. 한자 읽기 문제에서 보이는 한자를 그대로 옮겨 쓴 것은 정답이 아닙니다.
- **스스로 채점**: 뜻을 떠올리는 문제와 글자의 소리를 떠올리는 문제는 보기 없이 속으로 답한 뒤 정답을 보고(글자는 소리도 나옴) "알았어요/몰랐어요"를 고릅니다. 예전의 "글자 소리를 로마자로 쓰기" 문제는 없앴습니다.
- 근거와 자세한 규칙: [docs/DESIGN.md](docs/DESIGN.md)의 "누적 복습과 문제 난이도"와 "복습 하나로 · 일본어 자판 입력"

## 콘텐츠 수정하기
`js/data/ch*.js`의 각 화는 다음 형식입니다.
```js
{
  t: '제목', sub: '부제', tip: '오늘의 팁',
  kana: 'あ い う',                                  // 새 글자 (1장)
  v: [['がくせい', '学生', '학생', '學生 = 학생']],   // [읽기, 한자, 뜻, 메모]
  g: [{ t: 'AはBです', m: 'A는 B입니다', d: '설명(HTML)',
        x: [['わたし [は] 学生{がくせい} です 。', '저는 학생입니다.']] }],
  line: ['行{い}く ぞ ！', '간다!', '해설'],          // 오늘의 애니 대사
  dlg: { lines: [['화자', '대사', '번역']], q: ['질문', '정답', ['오답', '오답', '오답']] },
  note: ['인문학 제목', '본문']
}
```
예문 마크업: 공백 = 단어 구분 · `漢字{かんじ}` = 후리가나 · `[정답|오답|오답]` = 빈칸 문제 · `+토큰` = 앞 단어에 붙여 배열.

수정 후에는 검증을 실행하세요.
```bash
node tools/validate.js          # 콘텐츠 오류 검사
node tools/curriculum.js > docs/CURRICULUM.md
node tools/build.js             # dist/ 단일 파일 다시 만들기
```
