### 방법 0. Android 앱으로 설치 (추천)
**내려받기: https://github.com/hyogiman/jpnst/releases/latest/download/animimi.apk** (항상 최신 버전)
설치 안내 페이지: **https://2nhyeok.kr/apk** (휴대폰 Chrome 앱 주소창에 `2nhyeok.kr/apk` 입력 — 문제 해결 방법 포함)

1. 휴대폰 Chrome으로 위 주소를 열면 `animimi.apk`가 내려받아집니다. (웹 앱의 **나 → 휴대폰 앱으로 설치** 버튼도 같은 주소)
2. 내려받은 파일을 엽니다. 처음 한 번은 **"출처를 알 수 없는 앱 설치"** 를 허용해야 합니다. (Chrome 또는 내 파일 앱 → 허용 → 뒤로)
3. **설치 → 열기**. 홈 화면에 `アニ耳 일본어` 아이콘이 생깁니다.

- 앱 안에 모든 화면·음성(약 16MB)·글꼴이 들어 있어 **인터넷 없이도** 학습할 수 있습니다. 설치 파일은 약 26MB입니다.
- 새 버전이 나오면 같은 주소에서 받아 **덮어 설치**하면 학습 기록이 그대로 유지됩니다. (앱을 삭제하면 기록도 지워지니 나 → 백업 내보내기를 가끔 해 두세요)
- 앱은 인터넷에 연결되어 있을 때 6시간에 한 번 GitHub Releases의 최신 버전을 확인하고, 새 버전이 있으면 **홈 화면 맨 위에 안내**합니다. 나 → 설정 → **앱 버전**에서 지금 버전을 보고 직접 확인할 수도 있습니다. (1.0.2 이하 버전에는 이 기능이 없으니 한 번은 직접 내려받아 주세요)
- 웹(2nhyeok.kr)에서 하던 기록 옮기기: 웹의 **나 → 백업 내보내기** → 앱의 **나 → 백업 불러오기**에서 그 파일 선택
- 앱에서는 휴대폰 뒤로 가기 버튼으로 창 닫기 → 레슨 그만하기 확인 → 홈 → 앱 종료 순서로 동작하고, 백업은 공유 창(드라이브·카카오톡 등)으로 보냅니다.
- Play 스토어 밖에서 받은 앱이라 설치할 때 Play 프로텍트가 앱을 검사하겠냐고 물을 수 있습니다. 검사 후 설치하면 됩니다.
- **다운로드가 100%에서 멈추면**: 카카오톡·Claude 같은 다른 앱 안의 브라우저(맞춤 탭)에서는 "그래도 다운로드할까요?" 확인 창이 가려져 멈출 수 있습니다. 알림창이나 내 파일 → 다운로드에 파일이 있는지 보고, 없으면 Chrome 앱에서 다시 받으세요.
- 삼성 갤럭시에서 "자동 차단 기능에 의해 차단됨"이 뜨면 설정 → 보안 및 개인정보 보호 → 자동 차단 기능을 잠시 끄고 설치합니다.
- **iPhone**은 앱 파일 설치가 불가능하므로 아래 방법 1(Safari → 홈 화면에 추가)을 쓰세요.

**APK가 만들어지는 방식**: `main`에 앱 파일이 바뀌어 올라오면 GitHub Actions(`.github/workflows/android.yml`)가 [Capacitor](https://capacitorjs.com/)로 Android 앱을 빌드해 GitHub Releases에 올립니다. 버전 번호(versionCode)는 빌드마다 커지므로 항상 덮어 설치할 수 있습니다.

> **서명 키에 관한 주의**: 업데이트가 덮어 설치되려면 모든 APK가 같은 키로 서명되어야 합니다. 저장소 Secrets를 설정하지 않아도 바로 쓸 수 있도록 개인 배포용 키(`android/keystore/animimi-sideload.jks`, 비밀번호 `animimi-sideload`)를 저장소에 넣어 두었습니다. 공개 저장소이므로 누구나 같은 키로 서명한 APK를 만들 수 있다는 뜻이니, **APK는 반드시 위 Releases 주소에서만 받으세요.** 키를 비공개로 바꾸려면 새 키를 만들어 Settings → Secrets and variables → Actions에 `ANIMIMI_KEYSTORE_B64`(키 파일을 base64로 인코딩한 값), `ANIMIMI_KEYSTORE_PASSWORD`, `ANIMIMI_KEY_ALIAS`, `ANIMIMI_KEY_PASSWORD`를 넣으면 됩니다. 단, 키가 바뀌면 이미 설치한 앱은 한 번 삭제 후 다시 설치해야 합니다(그 전에 백업 내보내기).


### 방법 1. GitHub Pages + 도메인 `2nhyeok.kr` (현재 설정)
앱은 `main` 브랜치 루트에 있고, `CNAME` 파일에 `2nhyeok.kr`이 지정되어 있습니다.
1. 저장소 **Settings → Pages** 에서 Source를 `Deploy from a branch`, 브랜치 `main`, 폴더 `/ (root)`로 저장합니다.
2. 같은 화면의 **Custom domain**에 `2nhyeok.kr`이 들어가 있는지 확인합니다.
3. 도메인 업체(DNS 관리)에서 아래 레코드를 추가합니다.

   | 호스트 | 유형 | 값 |
   |---|---|---|
   | `@` | A | `185.199.108.153` |
   | `@` | A | `185.199.109.153` |
   | `@` | A | `185.199.110.153` |
   | `@` | A | `185.199.111.153` |
   | `www` | CNAME | `hyogiman.github.io` |

   (IPv6를 쓰려면 AAAA 레코드 `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`)
4. DNS가 반영되면(보통 몇 분~최대 48시간) Pages 화면에서 **Enforce HTTPS**를 켭니다.
5. 휴대폰에서 `https://2nhyeok.kr`을 열고 **홈 화면에 추가**하면 앱처럼 전체 화면으로 실행되고, 한 번 연 뒤에는 오프라인에서도 동작합니다.
   - iPhone(Safari): 공유 버튼 → 홈 화면에 추가
   - Android(Chrome): 메뉴 → 홈 화면에 추가 / 앱 설치

> 저장소가 비공개(private)라면 요금제에 따라 Pages 사용이 제한될 수 있습니다. 설정 방법은 GitHub 문서 "Managing a custom domain for your GitHub Pages site"를 참고하세요.

## 음성
- 기본은 **녹음 음성**입니다. 모든 가나·단어·예문·대사(2,086개 클립, 약 35MB)를 **구글 Cloud Text-to-Speech의 최신 음성(Chirp 3: HD)** 으로 미리 만들어 `audio/`에 넣어 두었습니다. 휴대폰에 일본어 음성이 없어도, 앱 안 브라우저에서도 같은 소리가 나고, 한 번 받으면 오프라인에서도 재생됩니다. 듣는 것은 구글에 접속하지 않으므로 몇 번을 들어도 비용이 들지 않습니다.
- **목소리 네 개를 섞어 씁니다**: 여성 **Despina·Sulafat**, 남성 **Algenib·Fenrir** (일본어 Chirp 3: HD 목소리 30개(여성 14·남성 16)를 같은 말로 만들어 학습자가 직접 듣고 고름).
  - 글자(가나): Despina 한 목소리로, 0.5배속으로 또렷하게
  - 단어: 네 목소리에 고르게 나눔. 소리 구별 짝(かき·かぎ 등)은 두 단어를 같은 목소리로
  - 예문·애니 대사: 남자 말투(おれ·お前·ぞ 등)는 남성, 여자 말투(わよ·かしら 등)는 여성, 나머지는 고르게
  - 장면 대화: 등장인물의 성별에 맞춰 인물마다 목소리 하나를 고정
  - 이유: 한 목소리로만 공부하면 그 목소리에 익숙해져서 맞히는 몫이 생깁니다(목소리 친숙성 효과). 그래서 처음부터 여러 목소리를 섞어 처음 듣는 목소리에도 대비합니다. 여러 화자 훈련의 이점은 원 연구(HVPT)에서 보고됐지만 대규모 재현 연구에서는 효과가 작게 나와, '반드시 더 낫다'기보다 손해 없는 선택으로 보는 것이 정확합니다(자세한 근거는 docs/DESIGN.md).
- **읽기는 후리가나와 똑같이**: 한 글자 한자(何·方·上 등 읽기가 여러 개인 것)는 후리가나로 바꿔 넣고, 두 글자 이상 한자는 일본어 요미가나 지정 기능으로 읽기를 지정합니다. 이 지정이 실제로 반영되는지는 今日(きょう/こんにち)·日本(にほん/にっぽん) 등 12건을 소리 모양 비교(MFCC + DTW)로 확인했습니다(11건 반영). 지정이 무시될 때를 대비해, 사전(Open JTalk)의 기본 읽기가 후리가나와 다른 말(日本→にほん, 九時→くじ, 辛い→からい, 一回→いっかい 등 16개 낱말)은 한자 대신 가나로 넣습니다.
- **가장 맑은 소리로**: 같은 입력도 만들 때마다 조금씩 달라 가끔 숨소리가 섞인 '아…'가 나옵니다. 그래서 글자는 4번, 단어는 3번, 문장은 2번 만들어 가장 맑은 것(조화음 대 잡음비가 가장 높은 것)을 자동으로 고르고, 모두 흐리면 몇 번 더 만듭니다.
- 96kbps MP3(48kbps에서 생기던 고음 손상 제거). 앞뒤 무음은 소리 끝을 자르지 않게 여유를 두고 줄입니다.
- **나 → 설정 → 음성 방식**에서 "기기 음성"으로 바꾸면 휴대폰 내장 음성(iPhone의 Kyoko 등)을 씁니다(웹 버전에서만). 이때 소리가 안 나면:
  - **Android**: 기종마다 메뉴 위치가 다르므로 설정 앱 검색창에 **"텍스트 음성 변환"** 을 검색 → 기본 엔진(Google 음성 서비스) → 음성 데이터 설치 → 일본어. Google 음성 서비스가 없으면 Play 스토어에서 "Google 음성 인식 및 합성"을 설치합니다.
  - **iPhone**: 설정 → 손쉬운 사용 → 읽기 및 말하기 → 음성 → 일본어.
- 콘텐츠를 고친 뒤 음성을 다시 만들려면:
  ```bash
  pip install "numpy<2" lameenc pyopenjtalk-prebuilt
  node tools/audio-texts.js > /tmp/audio-texts.json
  GOOGLE_TTS_KEY=<API 키> python3 tools/make-audio-google.py /tmp/audio-texts.json --cache /tmp/gtts-cache --report /tmp/gtts-report.json
  ```
  - API 키: Google Cloud 콘솔에서 Cloud Text-to-Speech API를 사용 설정하고 만든 키. **Text-to-Speech API로만 제한**하고, **저장소에는 절대 넣지 마세요.**
  - 비용: 전체를 한 번 만드는 데 약 3만 1천 자(여러 번 만들어 고르는 것 포함, 2026년 10월 실제 생성 기준). Chirp 3: HD는 한 달 100만 자까지 무료입니다([구글 가격표](https://cloud.google.com/text-to-speech/pricing), 2026년 10월 확인).
  - `--cache`를 쓰면 이미 만든 소리는 다시 요청하지 않아, 문장 몇 개를 고쳤을 때는 그 문장만 비용이 듭니다. `--dry`로 앱 파일을 건드리지 않고 시험할 수 있습니다.
  - 요청 속도: Chirp 3: HD의 기본 한도는 프로젝트당 **분당 200건**이라([구글 할당량 문서](https://cloud.google.com/text-to-speech/quotas)) 분당 150건으로 묶어 보냅니다(`--rpm`). 전체를 처음 만들면 요청이 약 6천 2백 건이라 40분 남짓 걸립니다. 한도에 걸려도(429) 잠시 쉬었다가 이어 갑니다.
- 인터넷·API 키 없이 만드는 방법(이전 음성): `tools/make-audio.py`는 VOICEVOX(VOICEVOX:冥鳴ひまり·玄野武宏)로 같은 형식의 음성을 만듭니다. 쓰려면 VOICEVOX core 0.15와 ONNX Runtime 1.13.1이 필요하고(파일 맨 위 설명 참고), 해당 캐릭터의 크레딧을 앱에 표시해야 합니다.
- 묶음 파일 이름에 내용 해시가 붙어(`pack0-1a2b3c4d.mp3`) 다시 만들면 휴대폰도 새 음성을 받습니다.

## 콘텐츠 수정하기
`js/data/ch*.js`의 각 화는 다음 형식입니다.
```js
{
  t: '제목', sub: '부제', tip: '오늘의 팁',
  kana: 'あ い う',                                  // 새 글자 (1장)
  v: [['がくせい', '学生', '학생', '學生 = 학생']],   // [읽기, 한자, 뜻, 메모]
  g: [{ t: 'AはBです', m: 'A는 B입니다', d: '설명(HTML)',
        x: [['わたし [は] 学生{がくせい} です 。', '저는 학생입니다.']] }],
  line: ['行{い}く ぞ ！', '간다!', '해설'],          // 오늘의 애니 대사
  dlg: { lines: [['화자', '대사', '번역']], q: ['질문', '정답', ['오답', '오답', '오답']] },
  note: ['인문학 제목', '본문']
}
```
예문 마크업: 공백 = 단어 구분 · `漢字{かんじ}` = 후리가나 · `[정답|오답|오답]` = 빈칸 문제 · `+토큰` = 앞 단어에 붙여 배열.

수정 후에는 검증을 실행하세요.
```bash
node tools/validate.js          # 콘텐츠 오류 검사
node tools/curriculum.js > docs/CURRICULUM.md
node tools/build.js             # dist/ 단일 파일 다시 만들기
```
